# Ketner AI

Кликабельный прототип веб-продукта в жанре AI-чата: интерфейс и UX воспроизводят поведение ChatGPT, но под капотом работают заглушки — без реального LLM, реальной авторизации и реальной оплаты.

Цель — показать инвесторам и пользователям полноценно работающий продукт и при этом заложить архитектуру так, чтобы заглушки позже заменились на реальные сервисы без переписывания фронтенда.

| ---- | --------------------------- | --------- |
| 1    | Каркас проекта и роутинг    | Готов     |
| 2    | UI чата и заглушка ИИ       | Не начат  |
| 3    | Заглушка авторизации        | Не начат  |
| 4    | Заглушка оплаты             | Не начат  |

Что уже работает: лендинг, каркас чата с пустым состоянием, витрина тарифов, экраны входа и регистрации, оформление подписки, настройки, онбординг, переключение темы и языка, обработка 404 и ошибок маршрута.

## Требования

- Node.js 20 или новее (разрабатывалось на 24.21)
- npm 10 или новее

## Установка и запуск

```bash
npm install
npm run dev
```

Поднимутся два процесса:

- фронтенд — http://localhost:5173
- mock-API — http://127.0.0.1:8787, описание контракта на http://127.0.0.1:8787/api

Запросы с фронтенда на `/api/*` проксируются на mock-API (настройка в `apps/web/vite.config.ts`), поэтому CORS в разработке не мешает.

Запуск по отдельности:

```bash
npm run dev:web
npm run dev:api
```

## Переменные окружения

Для прототипа обязательных переменных нет. Настройки mock-API перечислены в `apps/mock-api/.env.example`:

| Переменная    | Назначение         | Значение по умолчанию   |
| ------------- | ------------------ | ----------------------- |
| `PORT`        | Порт mock-API      | `8787`                  |
| `NODE_ENV`    | Окружение          | `development`           |
| `CORS_ORIGIN` | Разрешённый origin | `http://localhost:5173` |

Переменные, которые появятся на следующих этапах, перечислены в соответствующих документах: `AI_API_KEY`, `AUTH_*`, `PAYMENT_*`.

## Процесс работы

Разработка идёт этапами: после каждого этапа — остановка и подтверждение. Этап делается в отдельной ветке и попадает в `main` через pull request, перед которым прогоняются линтер, проверка типов и тесты.
