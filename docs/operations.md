# Деплой и эксплуатация

## Где что работает

| Что           | Где                                                   |
| ------------- | ----------------------------------------------------- |
| Домен и DNS   | Cloudflare (`ketner.org`, проксирование на Render)    |
| Сервер и сайт | Render, сервис `ketner-ai` (`ketner-ai.onrender.com`) |
| База          | Supabase Postgres                                     |
| Модели        | OpenRouter (один ключ, предоплаченный баланс)         |
| Картинки      | Cloudflare Workers AI, Runware                        |
| Оплата        | Trybit, Telegram Stars                                |
| Код           | GitHub `gumieeel/Ketner-AI`, ветка `main`             |

## Деплой

Каждый пуш в `main` Render выкатывает автоматически (примерно 1–3 минуты).

Настройки сервиса (`render.yaml`, проверьте и в панели — панель важнее файла):

- **Build Command:** `npm install && npm run build` — собирает сайт и сервер.
- **Start Command:** сейчас `npm start`. У `npm start` есть `prestart`, который **ещё раз собирает весь проект при каждом запуске**, в том числе после каждого «засыпания» бесплатного сервиса. Поставьте `node apps/mock-api/dist/server.js` — холодный старт станет быстрее.
- **Health Check Path:** `/api/health`.
- **Node:** задайте `NODE_VERSION=24` (в `package.json` требуется 22.12+, `Dockerfile` собирается на 24).
- **План:** `free` — сервис засыпает после 15 минут без запросов: первый посетитель и вебхуки ждут холодный старт, фоновые задачи не работают. Для продакшена нужен платный план (его требует и Trybit).

`apps/web/dist` закоммичен в git, и при этом Render собирает его заново. Если сборка фронтенда на Render упадёт, сервер отдаст закоммиченную версию. После правок сайта запускайте `npm run build` и коммитьте `dist`, чтобы обе копии совпадали.

Альтернатива Render — `Dockerfile` (многоэтапная сборка, Node 24, непривилегированный пользователь, healthcheck).

### Проверка после деплоя

```bash
curl -s https://ketner.org/api/health                  # {"status":"ok", "environment":"production"}
curl -sI https://ketner.org/assets/<имя из index.html>.js | grep -i content-type   # text/javascript, не text/html
```

Если `index.html` ссылается на отсутствующий файл, сайт покажет чёрный экран: SPA отдаёт HTML вместо скрипта. Затем откройте `/`, `/pricing`, `/chat` и проверьте консоль браузера.

## Первичная настройка (или переезд)

1. **Переменные** — по [environment.md](environment.md). Обязательны `BETTER_AUTH_SECRET`, `WEBHOOK_SECRET`, `ADMIN_API_KEY`; без `DATABASE_URL` данные пропадают при каждом деплое.
2. **База** — достаточно пустого Postgres: таблицы создаются при старте.
3. **Почта (SMTP)** — `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`. Обязательна: вход и регистрация по почте подтверждаются кодом из письма, без SMTP они отвечают `503 mail_unavailable` (войти можно будет только через Google / GitHub).
4. **Администратор** — `SEED_ADMIN_EMAIL` + `SEED_ADMIN_PASSWORD` на один запуск или почта в `ADMIN_EMAILS`. Для входа администратору тоже нужен код из письма: адрес должен быть настоящим.
5. **OAuth** — в консолях Google и GitHub колбэки `https://ketner.org/api/auth/callback/google` и `…/github` (с `BETTER_AUTH_URL=https://ketner.org`). Привязка репозиториев использует подкаталог `…/callback/github/repos`, его GitHub принимает без отдельной настройки.
6. **Telegram** — [telegram.md](telegram.md#настройка). Вебхуки бот ставит сам при старте.
7. **Trybit** — адреса успеха, неудачи и уведомлений ([payments.md](payments.md#trybit-криптовалюта)).
8. **Cloudflare** — проксирование включено (оранжевое облако), SSL Full (strict). Если сайт открывается ещё по каким-то адресам — добавьте их в `CORS_EXTRA_ORIGINS`.

## Секреты

- Генерация: `openssl rand -base64 32` (или `-hex 32`).
- Ротация `BETTER_AUTH_SECRET` разлогинивает всех и требует заново подключить GitHub; `WEBHOOK_SECRET`, `ADMIN_API_KEY` — без последствий для пользователей.
- Ключи провайдеров (OpenRouter, Trybit, Cloudflare, Runware, токены ботов) меняются в их кабинетах, затем в Environment Render. Всё, что когда-либо попадало в git или переписку, нужно перевыпустить ([auth-and-security.md](auth-and-security.md#известные-риски)).

## Админ-панель

`/admin` — для администраторов (или по ключу `x-admin-key`, который вводится в шапке панели и хранится в браузере).

| Блок                | Что показывает                                                                                                                                                              |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сводка              | Пользователи, запросы и токены за сутки, расход за месяц                                                                                                                    |
| Отрицательная маржа | Пользователи, у которых расход на модели больше выручки от тарифа (выручка с пакетов кредитов в этой метрике пока не учитывается: считается по цене прежней подписки)       |
| Регистрации         | По времени (часы, дни, недели) и часу суток, по способу входа и источнику (utm, сайт, реклама), кампании, последние регистрации; клик по строке фильтрует                   |
| Шлюз                | Попадания в кэш, задержки, расход по провайдерам и тарифам; «Модели за 30 дней» с вердиктом по кэшу промпта                                                                 |
| Пользователи        | Поиск, фильтр по тарифу, расход, остаток кредитов и их сгорание; ручная выдача кредитов; карточка: лимиты, рентабельность, 20 последних запросов; смена тарифа, VIP, админа |

Через админ-API без интерфейса: включение и выключение моделей и цены (`PATCH /api/admin/models/:id`, в том числе прямой API вендора), сброс предохранителя модели, курс рубля. Список — [api.md](api.md).

Источник регистрации записывается с 17.10.2026: сайт кладёт utm-метки, клик из рекламы (gclid/yclid) и внешний сайт в cookie `ketner_src`, сервер сохраняет их при создании аккаунта. Ставьте в рекламные ссылки `utm_source`, `utm_medium=cpc`, `utm_campaign`.

## Резервные копии

Все важные данные — в Supabase. Проверьте, какие резервные копии даёт ваш план Supabase (на бесплатном — ограниченно, без восстановления на момент времени), и хотя бы раз проверьте восстановление. Простой вариант — ежедневный `pg_dump` в отдельное хранилище по расписанию.

## Учебный помощник: выпуск и откат

Учебный помощник (шаблон-инструмент `study_assistant`) включается переменной `STUDY_ASSISTANT_ENABLED=true` в панели Render; по умолчанию выключен. Миграции `0007`–`0011` применяются сами при старте сервера и только добавляют: колонку `solutions.template`, таблицы `solution_materials`, `solution_runs`, `solution_attempts` и триггер `solutions_legacy_template`.

**Выключить функцию** (без отката кода): `STUDY_ASSISTANT_ENABLED=false` и перезапуск. Новые инструменты не создаются, галерея и рекомендации пропадают, уже созданные инструменты продолжают работать — данные пользователей доступны.

**Откат кода на версию до этапа Builder** (до миграции `0007`). Миграции не откатываются — старый код с новыми таблицами работает:

- помощники и боты: старый код вставляет их без `template` — триггер из `0011` ставит шаблон по типу; без триггера создание падало бы;
- инструменты (`type = 'tool'`): старый код не знает этот вид и показывает их как сломанных помощников (страница настроек без полей, чат с ошибкой, ссылка «Открыть чат»). Сохранение настроек через API записало бы поверх конфигурации инструмента конфигурацию помощника, удаление — удалило бы материалы, запуски и попытки. Выключение флага от этого **не** защищает: старый код флага не читает.

Поэтому перед откатом инструменты прячут от старого кода, ничего не удаляя.

1. `STUDY_ASSISTANT_ENABLED=false`, перезапуск; дождаться окончания идущих запусков (или принять, что они закроются как прерванные с честным списанием).
2. Резервная копия базы.
3. Спрятать инструменты (старый код ищет решения только по `user_id` и адресу бота, у инструментов адреса нет):

<!-- rollback:park -->

```sql
UPDATE solutions SET user_id = 'parked:' || user_id
WHERE type IN ('tool', 'workflow') AND user_id NOT LIKE 'parked:%';
```

4. Откатить код в Render (Manual Deploy нужного коммита).
5. После возврата новой версии вернуть инструменты владельцам (можно до или после её старта: спрятанные инструменты просто не видны):

<!-- rollback:unpark -->

```sql
UPDATE solutions SET user_id = substring(user_id FROM 8)
WHERE type IN ('tool', 'workflow') AND user_id LIKE 'parked:%';
```

Материалы, запуски, попытки и учёт кредитов при этом не меняются.

## Частые проблемы

| Симптом                                   | Причина и что делать                                                                      |
| ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| Чёрный экран на сайте                     | `index.html` ссылается на отсутствующий ассет: пересоберите и закоммитьте `apps/web/dist` |
| Все платные модели отвечают ошибкой       | Баланс или ключ OpenRouter (в логах 401/402)                                              |
| Первый запрос после паузы идёт минуту     | Бесплатный план Render засыпает; плюс `npm start` пересобирает проект (см. «Деплой»)      |
| После деплоя пропали данные               | Не задан или недоступен `DATABASE_URL`: смотрите строки `[db]` в логах при старте         |
| Бот не отвечает                           | Неверный токен или вебхук; проверьте `GET /api/telegram/status` и логи `[TelegramBot]`    |
| Страница «Изображения» пишет «недоступно» | Нет `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`                                      |
| Вход через Google ведёт на ошибку         | Колбэк в консоли Google не совпадает с `BETTER_AUTH_URL`                                  |
