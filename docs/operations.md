## Деплой

Каждый пуш в `main` Render выкатывает автоматически (примерно 1–3 минуты).

Настройки сервиса (`render.yaml`, проверьте и в панели — панель важнее файла):

- **Build Command:** `npm install && npm run build` — собирает сайт и сервер.
- **Start Command:** сейчас `npm start`. У `npm start` есть `prestart`, который **ещё раз собирает весь проект при каждом запуске**, в том числе после каждого «засыпания» бесплатного сервиса. Поставьте `node apps/mock-api/dist/server.js` — холодный старт станет быстрее.
- **Health Check Path:** `/api/health`.
- **Node:** задайте `NODE_VERSION=24` (в `package.json` требуется 22.12+, `Dockerfile` собирается на 24).
- **План:** `free` — сервис засыпает после 15 минут без запросов: первый посетитель и вебхуки ждут холодный старт, фоновые задачи не работают. Для продакшена нужен платный план (его требует и Trybit).

`apps/web/dist` закоммичен в git, и при этом Render собирает его заново. Если сборка фронтенда на Render упадёт, сервер отдаст закоммиченную версию. После правок сайта запускайте `npm run build` и коммитьте `dist`, чтобы обе копии совпадали.

Альтернатива Render — `Dockerfile` (многоэтапная сборка, Node 24, непривилегированный пользователь, healthcheck).

### Проверка после деплоя

```bash
curl -s https://ketner.org/api/health                  # {"status":"ok", "environment":"production"}
curl -sI https://ketner.org/assets/<имя из index.html>.js | grep -i content-type   # text/javascript, не text/html
```

Если `index.html` ссылается на отсутствующий файл, сайт покажет чёрный экран: SPA отдаёт HTML вместо скрипта. Затем откройте `/`, `/pricing`, `/chat` и проверьте консоль браузера.

## Первичная настройка (или переезд)

1. **Переменные** — по [environment.md](environment.md). Обязательны `BETTER_AUTH_SECRET`, `WEBHOOK_SECRET`, `ADMIN_API_KEY`; без `DATABASE_URL` данные пропадают при каждом деплое.
2. **База** — достаточно пустого Postgres: таблицы создаются при старте.
3. **Почта (SMTP)** — `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`. Обязательна: вход и регистрация по почте подтверждаются кодом из письма, без SMTP они отвечают `503 mail_unavailable` (войти можно будет только через Google / GitHub).
4. **Администратор** — `SEED_ADMIN_EMAIL` + `SEED_ADMIN_PASSWORD` на один запуск или почта в `ADMIN_EMAILS`. Для входа администратору тоже нужен код из письма: адрес должен быть настоящим.
5. **OAuth** — в консолях Google и GitHub колбэки `https://ketner.org/api/auth/callback/google` и `…/github` (с `BETTER_AUTH_URL=https://ketner.org`). Привязка репозиториев использует подкаталог `…/callback/github/repos`, его GitHub принимает без отдельной настройки.
6. **Telegram** — [telegram.md](telegram.md#настройка). Вебхуки бот ставит сам при старте.
7. **Trybit** — адреса успеха, неудачи и уведомлений ([payments.md](payments.md#trybit-криптовалюта)).
8. **Cloudflare** — проксирование включено (оранжевое облако), SSL Full (strict). Если сайт открывается ещё по каким-то адресам — добавьте их в `CORS_EXTRA_ORIGINS`.

## Секреты

- Генерация: `openssl rand -base64 32` (или `-hex 32`).
- Ротация `BETTER_AUTH_SECRET` разлогинивает всех и требует заново подключить GitHub; `WEBHOOK_SECRET`, `ADMIN_API_KEY` — без последствий для пользователей.
- Ключи провайдеров (OpenRouter, Trybit, Cloudflare, Runware, токены ботов) меняются в их кабинетах, затем в Environment Render. Всё, что когда-либо попадало в git или переписку, нужно перевыпустить ([auth-and-security.md](auth-and-security.md#известные-риски)).

Источник регистрации записывается с 17.10.2026: сайт кладёт utm-метки, клик из рекламы (gclid/yclid) и внешний сайт в cookie `ketner_src`, сервер сохраняет их при создании аккаунта. Ставьте в рекламные ссылки `utm_source`, `utm_medium=cpc`, `utm_campaign`.

## Резервные копии

Все важные данные — в Supabase. Проверьте, какие резервные копии даёт ваш план Supabase (на бесплатном — ограниченно, без восстановления на момент времени), и хотя бы раз проверьте восстановление. Простой вариант — ежедневный `pg_dump` в отдельное хранилище по расписанию.

## Учебный помощник: выпуск и откат

Учебный помощник (шаблон-инструмент `study_assistant`) включается переменной `STUDY_ASSISTANT_ENABLED=true` в панели Render; по умолчанию выключен. Миграции `0007`–`0011` применяются сами при старте сервера и только добавляют: колонку `solutions.template`, таблицы `solution_materials`, `solution_runs`, `solution_attempts` и триггер `solutions_legacy_template`.

**Выключить функцию** (без отката кода): `STUDY_ASSISTANT_ENABLED=false` и перезапуск. Новые инструменты не создаются, галерея и рекомендации пропадают.

> **Важно.** Флаг выключает только создание. **Уже созданные инструменты остаются рабочими:** владельцы могут загружать документы, запускать операции за кредиты, проходить тесты и запускать проверку. Поэтому выключение флага не останавливает запуски и не защищает данные при откате кода.

### Что будет при откате кода на версию до миграции `0007`

Миграции не откатываются — старый код работает с новыми таблицами:

- помощники и боты: старый код вставляет их без `template` — триггер из `0011` ставит шаблон по типу;
- инструменты (`type = 'tool'`): старый код не знает этот вид и показывает их как сломанных помощников (настройки без полей, чат с ошибкой). Сохранение настроек через API записало бы поверх конфигурации инструмента конфигурацию помощника, удаление — удалило бы материалы, запуски и попытки.

Поэтому на время отката инструменты прячут от старого кода, ничего не удаляя: к `user_id` решения добавляется префикс `parked:`. Старый код ищет решения только по `user_id` (и бота — по адресу, у инструментов адреса нет), поэтому спрятанные инструменты для него не существуют. Дочерние записи (материалы, запуски, попытки) хранят свой `user_id` и не меняются. Новый код спрятанные инструменты тоже не видит — это безопасно, их просто нет в списке до возврата.

### Как закрыть доступ пользователям (Render)

Нужно окно, в котором никто не может отправить запрос: иначе между проверкой «запусков нет» и пряткой кто-то запустит новую операцию.

- **Платный тариф web service — Maintenance Mode** (Settings → Maintenance Mode; в Blueprint — поле `maintenanceMode`). Процесс продолжает работать, но публичные запросы получают 503 со страницей обслуживания. Идущие запуски доходят до конца. Предпочтительный вариант.
- **Бесплатный тариф (сейчас в `render.yaml`: `plan: free`) — Suspend** (Settings → Suspend Web Service). Процесс останавливается, запросы не обслуживаются. Запуски, шедшие в этот момент, обрываются: новый код при возврате закроет их как прерванные и покажет, что успели списать. Чтобы таких было как можно меньше, сначала дождитесь, пока запусков не станет (шаг 2 ниже), и сразу приостановите сервис.

Перед первой процедурой проверьте в панели и документации Render: тариф сервиса, доступность переключателя, можно ли деплоить при включённом Maintenance Mode и какая версия запускается после Resume. Порядок шагов ниже безопасен при любом ответе: инструменты спрятаны всё время, пока может работать старая версия. Вебхуки (оплата, Telegram) в окне тоже получают ошибку — после открытия проверьте журнал оплат.

### Состояние — один запрос

Все проверки ниже — этот запрос (только чтение):

<!-- rollback:status -->

```sql
SELECT
  (SELECT count(*) FROM solutions
     WHERE type IN ('tool', 'workflow') AND user_id NOT LIKE 'parked:%') AS visible_tools,
  (SELECT count(*) FROM solutions
     WHERE type IN ('tool', 'workflow') AND user_id LIKE 'parked:%') AS parked_tools,
  (SELECT count(*) FROM solutions
     WHERE type IN ('tool', 'workflow') AND slug IS NOT NULL) AS tools_with_slug,
  (SELECT count(*) FROM solution_runs
     WHERE status IN ('queued', 'running') AND lease_expires_at > now()) AS active_runs,
  (SELECT count(*) FROM solution_runs
     WHERE status IN ('queued', 'running') AND lease_expires_at <= now()) AS stale_runs,
  (SELECT count(*) FROM solution_materials c JOIN solutions s ON s.id = c.solution_id
     WHERE c.user_id <> s.user_id)
  + (SELECT count(*) FROM solution_runs c JOIN solutions s ON s.id = c.solution_id
     WHERE c.user_id <> s.user_id)
  + (SELECT count(*) FROM solution_attempts c JOIN solutions s ON s.id = c.solution_id
     WHERE c.user_id <> s.user_id) AS mismatched_children;
```

- `active_runs` — запуски, которые ещё может завершить живой процесс (аренда не истекла; аренда — не больше 5 минут).
- `stale_runs` — оборванные запуски с истёкшей арендой: их никто не продолжит, новый код закроет их как прерванные. Прятке не мешают.
- `mismatched_children` — дочерние записи, чей `user_id` не совпадает с решением. В обычной работе — 0; пока инструменты спрятаны — число материалов, запусков и попыток спрятанных инструментов.

### Откат: новая версия → старая

1. `STUDY_ASSISTANT_ENABLED=false` (перезапуск). Запишите `visible_tools` из запроса состояния — это **N**, сколько инструментов будет спрятано.
2. Дождитесь `active_runs = 0` (запрос состояния, повторять раз в минуту).
3. **Закройте доступ**: Maintenance Mode или Suspend (см. выше). Снова запрос состояния: `active_runs` должно быть 0. При Suspend оборванный в последний момент запуск будет числиться в `active_runs`, пока не истечёт аренда — подождите до 5 минут, он перейдёт в `stale_runs`.
4. Резервная копия базы (`pg_dump` или снимок Supabase).
5. Спрятать инструменты — одной транзакцией. Блок сам проверяет, что идущих запусков нет, блокирует новые на время работы и при любой ошибке не меняет ничего:

<!-- rollback:park -->

```sql
DO $$
DECLARE
  active integer;
  parked integer;
BEGIN
  PERFORM set_config('lock_timeout', '10s', true);
  LOCK TABLE solutions, solution_runs IN SHARE ROW EXCLUSIVE MODE;
  SELECT count(*) INTO active FROM solution_runs
    WHERE status IN ('queued', 'running') AND lease_expires_at > now();
  IF active > 0 THEN
    RAISE EXCEPTION 'rollback:park: % active tool run(s), nothing changed; wait and retry', active;
  END IF;
  UPDATE solutions SET user_id = 'parked:' || user_id
    WHERE type IN ('tool', 'workflow') AND user_id NOT LIKE 'parked:%';
  GET DIAGNOSTICS parked = ROW_COUNT;
  RAISE NOTICE 'rollback:park: parked % solution(s)', parked;
END $$;
```

6. Проверка запросом состояния: `visible_tools = 0`, `parked_tools = N`, `tools_with_slug = 0`. Значит, ни один инструмент не доступен старому коду. Если блок упал — ничего не изменилось: устраните причину (обычно идущий запуск) и повторите. Повторный запуск блока безопасен.
7. Откатить код: Manual Deploy нужного коммита; дождитесь, что в панели Render он стал активным.
   - При Maintenance Mode деплой идёт, пока доступ закрыт.
   - При Suspend: Resume, затем Manual Deploy старого коммита. Пока деплой идёт, может отвечать новая версия — это безопасно: инструменты спрятаны, флаг выключен.
8. Открыть доступ (выключить Maintenance Mode). Помощники и боты работают, инструментов в старой версии нет.

### Возврат: старая версия → новая

Инструменты возвращаются владельцам только когда работает новая версия и до того, как пользователи её увидят. Старому коду вернувшиеся инструменты показывать нельзя.

1. Задеплойте новую версию.
   - Maintenance Mode: включите его, затем Manual Deploy новой версии; дождитесь, что она активна.
   - Suspend: Manual Deploy новой версии при открытом доступе (инструменты ещё спрятаны — новой версии это не мешает); дождитесь, что она активна, затем Suspend.
2. Вернуть инструменты — одной транзакцией. Блок проверяет, что дочерние записи каждого вернувшегося инструмента принадлежат тому же владельцу, иначе не меняет ничего:

<!-- rollback:unpark -->

```sql
DO $$
DECLARE
  restored integer;
  mismatched integer;
BEGIN
  PERFORM set_config('lock_timeout', '10s', true);
  LOCK TABLE solutions IN SHARE ROW EXCLUSIVE MODE;
  UPDATE solutions SET user_id = substring(user_id FROM 8)
    WHERE type IN ('tool', 'workflow') AND user_id LIKE 'parked:%';
  GET DIAGNOSTICS restored = ROW_COUNT;
  SELECT
    (SELECT count(*) FROM solution_materials c JOIN solutions s ON s.id = c.solution_id
       WHERE c.user_id <> s.user_id)
    + (SELECT count(*) FROM solution_runs c JOIN solutions s ON s.id = c.solution_id
       WHERE c.user_id <> s.user_id)
    + (SELECT count(*) FROM solution_attempts c JOIN solutions s ON s.id = c.solution_id
       WHERE c.user_id <> s.user_id)
  INTO mismatched;
  IF mismatched > 0 THEN
    RAISE EXCEPTION 'rollback:unpark: % child row(s) do not match their owner, nothing changed', mismatched;
  END IF;
  RAISE NOTICE 'rollback:unpark: restored % solution(s)', restored;
END $$;
```

3. Проверка запросом состояния: `parked_tools = 0`, `visible_tools = N`, `mismatched_children = 0` — у каждого инструмента его материалы, запуски и попытки снова принадлежат владельцу.
4. Открыть доступ (Resume или выключить Maintenance Mode). `stale_runs`, если были, новая версия закроет как прерванные при первом обращении владельца.

### Если процедура прервалась

Оба блока атомарны: инструменты либо все спрятаны, либо все на месте, частичного состояния не бывает. Запрос состояния показывает, где вы: `parked_tools > 0` — спрятаны.

- Откат отменили после пряток, а старый код так и не запускался: выполните возврат (шаги 2–3) и откройте доступ.
- Старая версия уже работает, а инструменты не спрятаны (шаг 5 пропущен): закройте доступ, выполните шаги 5–6, откройте доступ. Проверьте, не сохраняли ли в это время настройки инструментов через старую версию.
- Новая версия работает, а инструменты остались спрятаны: выполните возврат — новой версии он безопасен в любой момент.

Во время отката старая версия не считает спрятанные инструменты в лимите решений: после возврата у пользователя может оказаться больше решений, чем лимит, — новые создать нельзя, пока лишние не удалены. Существующие работают.

## Частые проблемы

| Симптом                                   | Причина и что делать                                                                      |
| ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| Чёрный экран на сайте                     | `index.html` ссылается на отсутствующий ассет: пересоберите и закоммитьте `apps/web/dist` |
| Все платные модели отвечают ошибкой       | Баланс или ключ OpenRouter (в логах 401/402)                                              |
| Первый запрос после паузы идёт минуту     | Бесплатный план Render засыпает; плюс `npm start` пересобирает проект (см. «Деплой»)      |
| После деплоя пропали данные               | Не задан или недоступен `DATABASE_URL`: смотрите строки `[db]` в логах при старте         |
| Бот не отвечает                           | Неверный токен или вебхук; проверьте `GET /api/telegram/status` и логи `[TelegramBot]`    |
| Страница «Изображения» пишет «недоступно» | Нет `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`                                      |
| Вход через Google ведёт на ошибку         | Колбэк в консоли Google не совпадает с `BETTER_AUTH_URL`                                  |
