# Архитектура и стек

## Общая схема

```
Браузер / Telegram мини-приложение / CLI и IDE
        │
        ▼
Cloudflare (ketner.org)  ──►  Render: один процесс Node (apps/mock-api/dist/server.js)
                                 ├─ /api/*      API сайта (Express)
                                 ├─ /v1/*       OpenAI-совместимый API по ключам
                                 ├─ /robots.txt, /sitemap.xml, SEO-страницы
                                 └─ всё остальное — SPA из apps/web/dist
                                        │
            ┌───────────────┬───────────┼──────────────┬──────────────┬─────────────┐
            ▼               ▼           ▼              ▼              ▼             ▼
      Supabase Postgres  OpenRouter  Прямые API    Cloudflare AI   Runware      Trybit, Telegram
      (все данные)       (все модели) (выключены)  (картинки)      (картинки)   Bot API (оплата)
```

Один процесс отдаёт и API, и сайт: отдельного фронтенд-хостинга нет. Название `mock-api` осталось с этапа прототипа — сейчас это боевой сервер.

## Хранение данных: память + Postgres

При старте (`server.ts` → `db/sync.ts: initDatabaseSync`) сервер:

1. создаёт недостающие таблицы и колонки (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE … ADD COLUMN IF NOT EXISTS`) — отдельного шага миграций нет;
2. загружает пользователей, диалоги, подписки, оценки, ключи API, журнал платежей, учёт расхода, обращения в поддержку и т. д. **в память**;
3. подключает «драйверы»: каждое изменение в хранилище сразу пишется в файл `apps/mock-api/data/*.json` и асинхронно — в Postgres.

Следствия:

- Читается всё из памяти — быстро, но **запускать можно только один экземпляр сервера**. Второй экземпляр не увидит изменений первого. Горизонтальное масштабирование потребует перевода хранилищ на прямые запросы к БД.
- Регион: сервис Render и база Supabase — Франкфурт (EU Central, у Supabase `eu-central-1`, инстанс t3a.nano, до 60 соединений). Регион указан в политике конфиденциальности.
- Диск Render временный: файлы в `data/` стираются при каждом деплое. Переживает деплой только то, что зеркалируется в Postgres. Что где хранится — [data-model.md](data-model.md).
- Ошибка записи в Postgres пишется в лог, но запрос пользователя не падает: изменение остаётся только в памяти до перезапуска.
- Без `DATABASE_URL` всё работает на файлах — так устроены локальная разработка и тесты.

## Путь запроса в чате

`POST /api/chat/completions` → `routes/chat.ts` → `AIGateway.stream` (`ai/gateway.ts`):

1. **Права** (`services/entitlement.ts`) — тариф, доступные модели, потолок ответа.
2. **Fair Use** (`services/fair-use.ts`) — сообщения и токены в сутки, параллельные запросы, дневной потолок расхода.
3. **Бюджет** (`services/budget-policy.ts`) — расход за 30 дней: 80% экономный режим, 100% только дешёвые модели, 125% отказ.
4. **Выбор модели** — Auto (`ai/auto-router.ts`) или явный выбор; недельный лимит модели (`ai/model-limits.ts`), квота премиум-моделей (`services/premium-quota.ts`), кредиты пакетов.
5. **Контекст** (`ai/context.ts`, `ai/workspace-context.ts`) — окно истории со сводкой, файлы привязанного проекта; точки кэша промпта (`ai/prompt-cache.ts`).
6. **Глубина размышлений** (`ai/reasoning-policy.ts`), режим Max на Ultra.
7. **Провайдер** — OpenRouter или прямой API вендора (`ai/providers/routed-provider.ts`), предохранитель на каждую модель (`ai/circuit-breaker.ts`), цепочка запасных моделей, сторож зависшего потока (`ai/stream-watchdog.ts`).
8. **Учёт** (`store/usage-store.ts`) — фактическая стоимость (`usage.cost` OpenRouter) по модели, которая реально ответила.

Ответ уходит потоком SSE (формат — [api.md](api.md#чат-sse)). Подробности моделей и экономики — [models-and-pricing.md](models-and-pricing.md).

Ketner Code (`code/agent-runner.ts`) и `/v1` (`ai/agent-gateway.ts`) используют те же бюджеты, квоты и учёт, но свой цикл вызовов.

## Сервер: `apps/mock-api/src`

| Папка         | Что внутри                                                                               |
| ------------- | ---------------------------------------------------------------------------------------- |
| `ai/`         | Шлюз, реестр и каталог моделей, Auto, лимиты, контекст, кэш, провайдеры, API для агентов |
| `auth/`       | Better Auth, Bearer-токены (`jwt.ts`), связь сессий Better Auth с аккаунтами сайта       |
| `billing/`    | `BillingService`: выдача тарифов и пакетов, журнал платежей, возвраты, валюты Trybit     |
| `code/`       | Ketner Code: проекты, файловая система, инструменты и цикл агента, песочница             |
| `db/`         | Схема Drizzle (для типов), синхронизация с Postgres (`sync.ts`)                          |
| `github/`     | OAuth-привязка GitHub и хранилище зашифрованных токенов                                  |
| `images/`     | Генерация картинок: Cloudflare, Runware, модерация, стили, хранение                      |
| `middleware/` | Аутентификация, гостевой id, лимиты частоты, заголовки безопасности и CORS, ошибки       |
| `routes/`     | Эндпоинты (список — [api.md](api.md))                                                    |
| `seo/`        | Мета-теги, robots, sitemap, статус 404 для несуществующих страниц                        |
| `services/`   | Цены, тарифы и бюджеты, маржа, курсы, Stripe, Trybit, почта, регистрации, VIP и админы   |
| `store/`      | Хранилища в памяти с файлами и зеркалом в Postgres                                       |
| `telegram/`   | Бот оплаты, бот поддержки, курс звёзд, подпись данных мини-приложения, коды привязки     |

Фоновые задачи внутри процесса: обновление курса звёзд (раз в час) и напоминания об автопродлении звёздами (за 3 дня до списания). Долгие потоки (агент Ketner Code, `/v1` со `stream`) шлют keepalive, чтобы прокси не рвал соединение. На бесплатном тарифе Render процесс засыпает через 15 минут без запросов, и эти задачи стоят.

## Сайт: `apps/web/src`

| Папка         | Что внутри                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| `app/`        | Провайдеры, синхронизация темы                                                                                |
| `components/` | `ui` (примитивы), `layout` (каркасы, сайдбар), `chat`, `code`, `images`, `marketing`, `docs`, `telegram`…     |
| `features/`   | Сторы и API-клиенты: `auth`, `chat`, `billing`, `code`, `images`, `usage`, `github`, `api-keys`, `content`    |
| `i18n/`       | Словари `ru.ts` (эталон) и `en.ts`                                                                            |
| `lib/`        | Утилиты: `cn`, `storage`, даты, безопасные ссылки, реклама (`ads.ts`), источник посетителя (`attribution.ts`) |
| `pages/`      | Экраны; страницы грузятся лениво (отдельный чанк на маршрут)                                                  |
| `router/`     | Маршруты ([screens.md](screens.md))                                                                           |
| `tests/`      | Vitest + Testing Library                                                                                      |

Сессия хранится в `localStorage` (Bearer-токен на 7 дней) и в cookie Better Auth для входа через Google и GitHub. Тема применяется до первой отрисовки инлайновым скриптом в `index.html`.

## Стек

| Слой             | Выбор                                                                     | Версия                 |
| ---------------- | ------------------------------------------------------------------------- | ---------------------- |
| Сайт             | React + TypeScript, Vite, Tailwind CSS                                    | 19.3 / 6.0 / 8.3 / 4.3 |
| Маршруты и стейт | React Router, Zustand                                                     | 7.18 / 5.0             |
| Сервер           | Node.js + Express                                                         | 22.12+ (24) / 5.2      |
| Аутентификация   | Better Auth (+ свои Bearer-токены)                                        | 1.7                    |
| База             | PostgreSQL (Supabase) через `postgres`; Drizzle — только схема и типы     | 3.4 / 0.45             |
| Почта            | nodemailer (любой SMTP)                                                   | 10                     |
| Модели           | OpenRouter; прямые API Anthropic, OpenAI, Google (выключены по умолчанию) | —                      |
| Тесты            | `node:test` (сервер), Vitest + Testing Library + jsdom (сайт)             | — / 5.0 / 16.3         |
| Линт и формат    | ESLint 10 (flat config), Prettier 3                                       | —                      |

**Почему не Next.js.** Продукт — приложение за входом, SEO нужно лендингу и нескольким страницам, а их мета-теги и `sitemap.xml` отдаёт сервер (`seo/pages.ts`). Серверу нужен долгий SSE-стриминг и фоновые задачи, поэтому отдельный Express проще route handlers. Переезд возможен: роуты и компоненты завязаны на React Router и `features/*`, менять пришлось бы точку входа и обращения к `localStorage`.

**Сознательно не подключено:** i18next (два языка, типизированный словарь проще), библиотеки иконок (иконки инлайновые в `components/icons`), clsx и tailwind-merge (свой `cn` с разрешением конфликтов классов), ORM для запросов (Drizzle только описывает схему, запросы — через `postgres`).
