# Вход, права и безопасность

## Как входят пользователи

| Способ         | Как устроено                                                                                                                                                                                                                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Почта и пароль | Регистрация в два шага: `POST /api/auth/signup` отправляет 6-значный код на почту и отдаёт `signupId`, `POST /api/auth/signup/verify` с кодом создаёт аккаунт (`auth/signup-verification.ts`). Вход — `POST /api/auth/login`. Оба выдают свой Bearer-токен (HS256, 7 дней). Пароль — scrypt (N=2¹⁵); старые хеши PBKDF2 заменяются при входе. Пароль от 8 символов |
| Google, GitHub | Better Auth (`authClient.signIn.social`) → cookie-сессия; аккаунт сайта создаётся при первом запросе (`middleware/auth.ts`)                                                                                                                                                                                                                                        |
| Telegram       | Подтверждение входа в боте или одноразовая ссылка из кабинета ([telegram.md](telegram.md))                                                                                                                                                                                                                                                                         |
| Гость          | Без входа можно писать в чат: подписанный id `guest_…`, бесплатная модель, 15 сообщений в час и 40 в сутки с IP                                                                                                                                                                                                                                                    |

Аккаунт сайта (`ketner_users`) и запись Better Auth связаны почтой. Сессия Better Auth открывает аккаунт сайта только если почта подтверждена провайдером или запись создана вместе с аккаунтом; служебные адреса Telegram через Better Auth не открываются никогда (`auth/better-auth-sync.ts`). При входе и регистрации по паролю пароль записи Better Auth приводится к паролю владельца, а посторонние сессии отзываются.

Из браузера доступен только белый список эндпоинтов Better Auth (`middleware/security.ts`: получение сессии, выход, вход по паролю и через провайдера, колбэки OAuth, список и отзыв сессий). Регистрация, смена почты и пароля, удаление и сброс через Better Auth закрыты.

Выход (`POST /api/auth/logout`) отзывает Bearer-токен на сервере (`revoked_tokens`).

## Права

- **Тариф** — `plan` пользователя с проверкой срока подписки (`services/plan-resolver.ts`). Тариф и личность берутся только из сессии, никогда из тела запроса или заголовков клиента.
- **VIP** — почты из `VIP_EMAILS` или флаг в админке: Ultra без оплаты.
- **Администратор** — почты из `ADMIN_EMAILS` или флаг в админке; либо заголовок `x-admin-key: <ADMIN_API_KEY>` для админ-API. В коде нет ни одного зашитого адреса. В production адреса администраторов и VIP нельзя занять регистрацией по паролю.
- **API-ключи** `ketner_sk_…` — от имени владельца, с тем же тарифом и бюджетом; хранится только SHA-256 ([agent-api.md](agent-api.md)).

## Защита

- **Секреты** обязательны в production и не короче 32 символов; значения, когда-либо лежавшие в репозитории, отклоняются (`config.ts`).
- **CORS** — только свои адреса (`CORS_ORIGIN`, `CORS_EXTRA_ORIGINS`, ketner.org и Render).
- **Заголовки** — CSP (скрипты только со своего домена, telegram.org, тега Google Ads и по хешам inline-скриптов `index.html`), HSTS, `nosniff`, Referrer-Policy, `frame-ancestors` с учётом web.telegram.org; без `X-Powered-By`.
- **Лимиты частоты** (в памяти, сбрасываются при деплое): неудачные входы — 30 за 15 минут с IP и 8 на почту; регистрации — 5 в час с IP; письма с кодом — 6 в час на почту, повтор не чаще раза в минуту; код — 10 минут и 5 попыток, ввод кода — 30 за 15 минут с IP; вход через Telegram; гостевые сообщения и диалоги. Реальный IP — через `trust proxy`, `CF-Connecting-IP` учитывается только от адресов Cloudflare.
- **Тело запроса** — 1 МБ по умолчанию, до 50 МБ только там, где нужно (вложения, импорт).
- **Ошибки** — 500 не раскрывает внутренний текст; карта API (`GET /api`) в production не публикуется.
- **Markdown** — ссылки только http(s), mailto и tel (защита от `javascript:`).
- **Вебхуки** — подписи Trybit (JWT + перепроверка), Telegram (секрет в заголовке), Stripe и общий HMAC; выдача тарифа идемпотентна по id платежа.
- **GitHub** — токены зашифрованы AES-256-GCM, браузер ходит через прокси со списком разрешённых операций ([code-workspace.md](code-workspace.md)).
- **Картинки** — обязательная модерация, файлы по подписанным ссылкам на 6 часов.

Регрессионные тесты аудита: `apps/mock-api/src/security-regressions.test.ts`, `apps/web/src/tests/safe-url.test.tsx`.

## Известные риски

| Риск                                                                                                              | Что сделать                                                                           |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Ключи, которые когда-то были в истории git (OpenRouter, токены ботов) и в переписке (Trybit, Cloudflare, Runware) | Отозвать у провайдеров и выпустить новые, если ещё не сделано                         |
| Bearer-токен лежит в `localStorage` и живёт 7 дней: при XSS его можно украсть                                     | Перевести на httpOnly-cookie или сократить срок с обновлением                         |
| Нет «Забыли пароль?» и подтверждения почты                                                                        | Почтовые сценарии через SMTP, который уже подключён для Telegram                      |
| Нет удаления аккаунта и выгрузки данных (требование законов о персональных данных)                                | Эндпоинт удаления с каскадом по всем хранилищам и выгрузка в JSON                     |
| Прямой адрес `*.onrender.com` открыт в обход Cloudflare                                                           | Принимать запросы только от Cloudflare или редиректить на ketner.org                  |
| Вход через Telegram — device-flow: можно прислать жертве ссылку на подтверждение                                  | Бот предупреждает и показывает устройство; при злоупотреблениях — короткий код сверки |
| Лимиты частоты в памяти: сбрасываются при деплое, не работают при нескольких экземплярах                          | Хранить в Postgres или Redis при масштабировании                                      |
| Бесплатные `:free`-модели OpenRouter могут логировать промпты Free-пользователей                                  | Отражено должно быть в `/privacy`; проверьте текст                                    |
