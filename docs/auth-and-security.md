# Вход, права и безопасность

## Как входят пользователи

| Способ         | Как устроено                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Почта и пароль | Всегда в два шага, второй — 6-значный код из письма (`auth/email-codes.ts`). Регистрация: `POST /api/auth/signup` → `POST /api/auth/signup/verify` создаёт аккаунт. Вход: `POST /api/auth/login` (почта и пароль) → `POST /api/auth/login/verify`. Повтор кода — `…/resend`. После кода сервер выдаёт свой Bearer-токен (HS256, 7 дней) и сам ставит cookie-сессию Better Auth; вход в Better Auth по паролю напрямую (`/api/auth/sign-in/email`) закрыт. Пароль — scrypt (N=2¹⁵); старые хеши PBKDF2 заменяются при входе. Пароль от 8 символов |
| Google, GitHub | Better Auth (`authClient.signIn.social`) → cookie-сессия; аккаунт сайта создаётся при первом запросе (`middleware/auth.ts`)                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Telegram       | Входа на сайт через Telegram нет. Telegram только привязывается к аккаунту — для кабинета кредитов в боте ([telegram.md](telegram.md))                                                                                                                                                                                                                                                                                                                                                                                                           |
| Гость          | Без входа можно писать в чат: подписанный id `guest_…`, бесплатная модель, 15 сообщений в час и 40 в сутки с IP                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Аккаунт сайта (`ketner_users`) и запись Better Auth связаны почтой. Сессия Better Auth открывает аккаунт сайта только если почта подтверждена провайдером или запись создана вместе с аккаунтом; служебные адреса Telegram через Better Auth не открываются никогда (`auth/better-auth-sync.ts`). При входе и регистрации по паролю пароль записи Better Auth приводится к паролю владельца, а посторонние сессии отзываются.

Из браузера доступен только белый список эндпоинтов Better Auth (`middleware/security.ts`: получение сессии, выход, вход по паролю и через провайдера, колбэки OAuth, список и отзыв сессий). Регистрация, смена почты и пароля, удаление и сброс через Better Auth закрыты.

Выход (`POST /api/auth/logout`) отзывает Bearer-токен на сервере (`revoked_tokens`).

### Восстановление пароля

«Забыли пароль?» на странице входа (`/login/forgot` → `/login/forgot/verify` → `/login/forgot/new`):

1. `POST /api/auth/password-reset` с почтой — код на почту тем же механизмом, что вход и регистрация (5 минут, 5 попыток; у писем сброса свой лимит на почту — см. «Защита»). Ответ одинаковый, есть аккаунт или нет: для неизвестной почты и служебных адресов Telegram заявка заводится, но письмо не уходит — по ответу не узнать, зарегистрирована ли почта.
2. `POST /api/auth/password-reset/verify` с кодом — одноразовый токен на 15 минут (`auth/password-reset.ts`, хранится только хеш). Сессии ещё нет. Повтор кода — `…/resend`.
3. `POST /api/auth/password-reset/complete` с токеном и новым паролем (от 8 символов) — пароль меняется, прежние сессии завершаются, открывается новая (Bearer-токен и cookie Better Auth), счётчик неудачных входов по почте обнуляется.

Прежние сессии: в Bearer-токене есть отпечаток пароля (`cred`, `userStore.credentialStamp`), при смене пароля он меняется, и `middleware/auth.ts` такие токены не принимает (токены, выданные до появления отпечатка, действуют до своего срока — не дольше 7 дней). Cookie-сессии Better Auth с этой почтой удаляются (`revokeBetterAuthSessions`).

## Права

- **Уровень доступа** — `plan` пользователя с проверкой срока прежней подписки (`services/plan-resolver.ts`); у остальных `free`, а пока есть неистраченные купленные кредиты эффективный уровень вычисляется как `credits` (`services/user-plan.ts`, в базе не хранится). Тариф и личность берутся только из сессии, никогда из тела запроса или заголовков клиента.
- **VIP** — почты из `VIP_EMAILS` или флаг в админке: Ultra без оплаты.
- **Администратор** — почты из `ADMIN_EMAILS` или флаг в админке; либо заголовок `x-admin-key: <ADMIN_API_KEY>` для админ-API. В коде нет ни одного зашитого адреса. В production адреса администраторов и VIP нельзя занять регистрацией по паролю.
- **API-ключи** `ketner_sk_…` — от имени владельца, с тем же уровнем доступа и кредитами; хранится только SHA-256 ([agent-api.md](agent-api.md)).
- **Анализы гостей (Business Discovery на главной)** принадлежат гостевому id `guest_…` этого браузера. С 06.11.2026 сайт создаёт id из `crypto.getRandomValues` — 24 символа `[a-z0-9]`, ≈124 бита (раньше — `Math.random` и время, ≈46 бит; такие старые id продолжают работать, чтобы гости не потеряли свои чаты и анализы). Анализ и без того адресуется UUID и виден только владельцу, а чтение гостями ограничено 300 запросами в минуту с IP. Анализ гостя, не перенесённый в аккаунт, живёт 30 дней: потом не читается и стирается (как удалённый — запись остаётся для суточных лимитов). После входа или регистрации список анализов переносит в аккаунт все живые анализы гостя этого браузера (`claimAllGuest`), страница анализа — открытый.
- **Диалоги** читаются и меняются только владельцем: чужой id — 404. Гостевой диалог (владелец вида `guest_…`) переходит в аккаунт после входа, только если гостевой id из заголовка `X-Guest-Id` этого браузера совпадает с владельцем (`conversationStore.claimGuestConversation`, с 30.10.2026). Раньше `get` переназначал любой найденный по id диалог тому, кто его открыл.

## Защита

- **Секреты** обязательны в production и не короче 32 символов; значения, когда-либо лежавшие в репозитории, отклоняются (`config.ts`).
- **CORS** — только свои адреса (`CORS_ORIGIN`, `CORS_EXTRA_ORIGINS`, ketner.org и Render).
- **Заголовки** — CSP (скрипты только со своего домена, telegram.org, тега Google Ads и по хешам inline-скриптов `index.html`), HSTS, `nosniff`, Referrer-Policy, `frame-ancestors` с учётом web.telegram.org; без `X-Powered-By`.
- **Лимиты частоты** (в памяти, сбрасываются при деплое): неудачные входы — 30 за 15 минут с IP и 8 на почту; регистрации — 5 в час с IP; письма с кодом — 10 в час на почту для входа и регистрации, отдельно 5 в час на почту для сброса пароля (его можно запросить для чужой почты — это не должно мешать владельцу войти), всего 30 в час с IP, повтор не чаще раза в минуту; код — 5 минут и 5 попыток, ввод кода — 30 за 15 минут с IP; вход через Telegram; гостевые сообщения и диалоги. Реальный IP — через `trust proxy`, `CF-Connecting-IP` учитывается только от адресов Cloudflare.
- **Тело запроса** — 1 МБ по умолчанию, до 50 МБ только там, где нужно (вложения, импорт).
- **Ошибки** — 500 не раскрывает внутренний текст; карта API (`GET /api`) в production не публикуется.
- **Markdown** — ссылки только http(s), mailto и tel (защита от `javascript:`).
- **Вебхуки** — подписи Trybit (JWT + перепроверка), Telegram (секрет в заголовке), Stripe и общий HMAC; выдача кредитов идемпотентна по id платежа.
- **GitHub** — токены зашифрованы AES-256-GCM, браузер ходит через прокси со списком разрешённых операций ([code-workspace.md](code-workspace.md)).
- **Картинки** — обязательная модерация, файлы по подписанным ссылкам на 6 часов.

Регрессионные тесты аудита: `apps/mock-api/src/security-regressions.test.ts`, `apps/web/src/tests/safe-url.test.tsx`.

## Известные риски

| Риск                                                                                                              | Что сделать                                                          |
| ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Ключи, которые когда-то были в истории git (OpenRouter, токены ботов) и в переписке (Trybit, Cloudflare, Runware) | Отозвать у провайдеров и выпустить новые, если ещё не сделано        |
| Bearer-токен лежит в `localStorage` и живёт 7 дней: при XSS его можно украсть                                     | Перевести на httpOnly-cookie или сократить срок с обновлением        |
| Нет удаления аккаунта и выгрузки данных (требование законов о персональных данных)                                | Эндпоинт удаления с каскадом по всем хранилищам и выгрузка в JSON    |
| Прямой адрес `*.onrender.com` открыт в обход Cloudflare                                                           | Принимать запросы только от Cloudflare или редиректить на ketner.org |
| Лимиты частоты в памяти: сбрасываются при деплое, не работают при нескольких экземплярах                          | Хранить в Postgres или Redis при масштабировании                     |
| Бесплатные `:free`-модели OpenRouter могут логировать промпты Free-пользователей                                  | Отражено должно быть в `/privacy`; проверьте текст                   |
