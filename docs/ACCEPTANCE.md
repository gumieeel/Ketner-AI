## 2. Что сделать владельцу

1. **Замерить модели** — с ключом OpenRouter (production-ключ или отдельный на staging):

   ```bash
   cd apps/mock-api
   OPENROUTER_API_KEY=… npm run bench:discovery -- --mode free --out bench-free.json
   OPENROUTER_API_KEY=… npm run bench:discovery -- --mode paid --limit 10 --out bench-paid.json
   ```

   Бесплатный режим на 20 задачах стоит порядка $0.1–0.3 баланса ключа; кредиты пользователей не трогаются. Пороги, при которых модель годится (раздел 3), — ориентир; если GPT-6 Luna их не проходит, решение по модели бесплатного сценария (решение 7 в MIGRATION_PLAN.md) пересматривается до включения флага.

2. **Флаг** — с 01.11.2026 платформа включена по умолчанию (в коде), в панели Render ничего ставить не нужно. Переменная описана в `render.yaml` с `sync: false` только для отката.

3. **Проверить после включения** (сделано при выкатке 01.11.2026, повторять после крупных изменений):
   - лог запуска Render: миграции `0001_discovery` … `0004_solutions` применены (`migrations: applied` или «уже применены»), ошибок `discovery unavailable` нет;
   - `https://ketner.org/` содержит `<meta name="ketner-features" content="discovery">`;
   - один настоящий анализ гостем в приватном окне: вопросы → отчёт → краткий план, кредиты не списаны;
   - после входа: подробный план за кредиты, создание и проверка помощника, сообщение в чате помощника; списания видны в «Кредитах».

4. **Откат** — `DISCOVERY_ENABLED=false` в той же панели. Данные анализов и помощников остаются в базе; маршруты снова отвечают 404, чат и оплата не затронуты.

## 3. Замер качества: что считается

`apps/mock-api/src/scripts/benchmark-discovery.ts` прогоняет 20 типичных задач на русском (магазин, бухгалтерия, школа, юрист, поддержка, производство и др.; в 10 из них пользователь называет частоту и длительность задачи) через настоящий `DiscoveryService` — те же промпты, схемы, повтор при невалидном JSON и проверки, что на сайте. Уточняющие вопросы получают короткий ответ, как от занятого человека; затем строится план для первой выполнимой возможности (краткий в бесплатном режиме, подробный в платных).

| Метрика                                 | Что значит                                                                                              | Ориентир для бесплатной модели   |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `reports`                               | Доля задач, дошедших до отчёта                                                                          | ≥ 95%                            |
| `validJsonFirstTry`                     | Ответ прошёл схему с первой попытки — по этапам «контекст», «поиск возможностей», «план»                | ≥ 85% (повтор спасает остальное) |
| `opportunitiesAvg`, `reportsWithin3to7` | Сколько возможностей в отчёте; доля отчётов с 3–7 возможностями (требование промпта)                    | ≥ 90% в диапазоне                |
| `feasibility`                           | Распределение статусов выполнимости по каталогу — проверка, что модель не предлагает только недоступное | `not_supported` < 30%            |
| `numbersHonest`                         | Расчёт экономии есть, только когда пользователь дал числа; без чисел — нет выдуманных часов             | ≥ 80%                            |
| `costUsd`, `durationMs`                 | Себестоимость задачи и время до отчёта с планом                                                         | ≤ $0.02 и ≤ 90 с на задачу       |

Результат по каждой задаче сохраняется в файл `--out` (JSON); итог печатается в консоль.

## 4. Что осталось за рамками этапа

- Бесплатная правка ответов после отчёта — решение владельца: пока платно, вернуться позже.
- Builder: только тип «персональный помощник»; контент и процессы — следующие типы решений.
- Интеграции помощника (почта, CRM) не имитируются: такие возможности получают статус «подключить» или «не поддерживается».
