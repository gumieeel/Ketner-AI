# Технологический стек

Документ фиксирует стек и причины выбора. Версии соответствуют фактически установленным.

## Итоговый стек

| Слой                 | Выбор                                | Версия            | Почему так                                                                      |
| -------------------- | ------------------------------------ | ----------------- | ------------------------------------------------------------------------------- |
| Сборка фронтенда     | Vite                                 | 8.3               | Быстрый dev-сервер и мгновенный HMR; прототип — это SPA, SSR не нужен           |
| UI                   | React + TypeScript                   | 19.3 / 6.0.3      | Стандарт рынка, строгая типизация контрактов с mock-API                         |
| Стили                | Tailwind CSS (+ `@tailwindcss/vite`) | 4.3               | CSS-first конфигурация, тёмная тема через класс, быстрая вёрстка                |
| Маршрутизация        | React Router                         | 7.18              | Вложенные layout-маршруты (каркас приложения / маркетинг)                       |
| Состояние            | Zustand                              | 5.0               | Два стора без провайдеров: настройки UI и чат (диалоги, сообщения, стриминг)    |
| Локализация          | Свой словарь + хук `useTranslation`  | —                 | Два языка и ~120 строк: тянуть i18next пока незачем                             |
| Mock-API             | Node.js + Express + TypeScript       | 5.2               | Один язык и один `npm install` на весь репозиторий; SSE для стриминга тривиален |
| Запуск TS на сервере | tsx                                  | 4.23              | Быстрый watch-режим без сборки                                                  |
| Монорепо             | npm workspaces                       | npm 11.19         | Встроено в npm, дополнительные инструменты не нужны                             |
| Тесты фронтенда      | Vitest + Testing Library + jsdom     | 5.0 / 16.3 / 30.1 | Тот же конфиг, что и Vite                                                       |
| Тесты mock-API       | `node:test` + встроенный `fetch`     | Node 24           | Smoke-тесты контракта без дополнительных зависимостей                           |
| Линт и формат        | ESLint (flat config) + Prettier      | 10.0 / —          | Один конфиг на оба воркспейса                                                   |

Требуется Node.js 20 или новее (проект разрабатывался на 24.21).

## Почему не Next.js

Развилка была основной при выборе стека. Причины отказа:

- Продукт — авторизованное SPA-приложение, а не контентный сайт: SEO важно только для лендинга и страницы тарифов.
- Mock-API нужен отдельным процессом с SSE-стримингом; в Next.js его пришлось бы либо встраивать в route handlers, либо всё равно поднимать отдельный сервис — то есть выгоды нет, а конфигурации больше.
- Прототип должен запускаться одной командой и быстро собираться; SSR добавляет режимы рендера, гидратацию и ограничения на использование браузерных API (`localStorage` для сессии и темы).

Если проект всё же переедет на Next.js, менять придётся: точку входа (`src/main.tsx` / `App.tsx`), конфигурацию Vite, и места прямого обращения к `localStorage`. Роуты и компоненты переносятся почти без изменений, потому что уже опираются на React Router и слой `features/*`.

## Что сознательно не подключено

- **i18next / react-i18next** — при двух языках словарь `src/i18n/*.ts` проще и полностью типизирован: ключи проверяются на этапе компиляции.
- **clsx / tailwind-merge** — вместо них функция `cn` в `src/lib/cn.ts`; конфликтов классов в текущей вёрстке нет.
- **Middleware `persist` из Zustand** — тема дублируется в плоский ключ `ketner.theme`, потому что его читает инлайновый скрипт в `index.html` для защиты от вспышки светлого фона.
- **Storybook** — прототип смотрят целиком, а не по компонентам.
- **Библиотека иконок** — иконки инлайновые (`src/components/icons`): 20 иконок, нулевой вес, никаких лишних зависимостей.

## Структура репозитория

```
apps/
  web/                    фронтенд (Vite + React)
    src/
      app/                сквозные провайдеры (синхронизация темы)
      components/
        icons/            инлайновые иконки
        layout/           каркасы: AppShell, StandaloneLayout, сайдбар, шапка
        ui/               примитивы: Button, Input, Field, Badge, Card
      features/
        billing/          каталог тарифов
        chat/             стор чата, SSE-клиент, markdown, компоненты ленты и композера
        preferences/      тема, язык, выбранная модель, состояние сайдбара
      i18n/               словари ru/en и хук перевода
      lib/                утилиты (cn, storage)
      pages/              экраны
      router/             маршруты
      tests/              тесты экранов, чата, сайдбара и парсера markdown
  mock-api/               заглушка backend-API (Express)
    src/
      ai/                 шаблоны ответов, каталог моделей, стриминг текста
      middleware/         единый формат ошибок
      routes/             эндпоинты
      store/              файловое хранилище диалогов
      testing/            хелперы для тестов контракта
    data/                 файл хранилища во время работы (в git не попадает)
docs/                     проектная документация
```

## Команды

| Команда                               | Что делает                                               |
| ------------------------------------- | -------------------------------------------------------- |
| `npm install`                         | Устанавливает зависимости обоих воркспейсов              |
| `npm run dev`                         | Поднимает mock-API (8787) и фронтенд (5173) одновременно |
| `npm run dev:web` / `npm run dev:api` | Только фронтенд / только API                             |
| `npm run build`                       | Сборка обоих воркспейсов                                 |
| `npm run typecheck`                   | Проверка типов без эмита                                 |
| `npm run lint`                        | ESLint по всему репозиторию                              |
| `npm test`                            | Тесты фронтенда и smoke-тесты mock-API                   |
| `npm run format`                      | Prettier с автоисправлением                              |

## Соглашения

- Импорты внутри `apps/web` — через алиас `@/` (настроен и в `vite.config.ts`, и в `tsconfig.json`).
- В `apps/mock-api` импорты с расширением `.js`: так требует NodeNext-резолюция при сборке в ESM.
- Комментарии и UI-тексты — на русском; идентификаторы и код — на английском.
- Пользовательские строки не хардкодятся в компонентах, а берутся из словаря `src/i18n`.
