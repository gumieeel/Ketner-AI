# SEO: как сайт отдаётся поисковикам

Сайт — SPA на React, но поисковик получает готовую страницу: заголовок, описание, разметку Schema.org и весь текст в HTML, без выполнения JavaScript.

## Как устроено

| Что                                                                              | Где                                                                                                    |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Список открытых страниц: имя, title, description, canonical, попадание в sitemap | `apps/mock-api/src/seo/seo-pages.json` — один файл для сервера и сайта                                 |
| Метатеги, canonical, Open Graph, Schema.org, robots.txt, sitemap.xml             | `apps/mock-api/src/seo/pages.ts`                                                                       |
| Отрисовка страниц в HTML при сборке                                              | `apps/web/src/entry-prerender.tsx`, `apps/web/scripts/prerender.mjs` → `apps/web/dist/.prerender.json` |
| Заголовок вкладки при переходах внутри сайта                                     | `StandaloneLayout` (`lib/seo-pages.ts`)                                                                |

**Предварительная отрисовка.** `npm run build` в `apps/web` после `vite build` собирает `entry-prerender.tsx` для Node и рендерит каждую страницу из `seo-pages.json` так, как её видит гость (русский язык, тёмная тема). Сервер вставляет эту разметку в `<div id="root">`. В браузере `main.tsx` дожидается кода текущей страницы и заменяет разметку живым приложением, поэтому пустого экрана между ними нет. Без JavaScript страница видна целиком; главная — около 1000 слов текста и 37 внутренних ссылок.

**Две главные.** Сервер пишет в HTML каждой страницы `<meta name="ketner-features">` с включёнными возможностями (`DISCOVERY_ENABLED` → `discovery`), сайт читает её при запуске (`apps/web/src/lib/features.ts`). При включённом флаге главная — «Расскажите о своём бизнесе» (Business Discovery): её разметка собирается отдельным вариантом `discovery:/` (`PRERENDER_VARIANTS` в `entry-prerender.tsx`), заголовок и описание — из поля `discovery` записи `/` в `seo-pages.json`, Schema.org — с новым описанием. Прежний посыл («ChatGPT, Claude, Gemini и Grok в одном чате») — у `/models`, вопросы и ответы (FAQPage) — у `/pricing`. Без флага всё как раньше.

Если страница при отрисовке обращается к `window`, `document` или `localStorage` вне эффектов, сборка падает (и тест `tests/prerender.test.tsx`). Обращения к браузеру держите в `useEffect`.

**Что получает каждый адрес**

- Открытые страницы (`seo-pages.json`): свой `title` и `description`, `canonical`, `robots: index`, Open Graph и Twitter-превью (`/og-image.png`, 1200×630), хлебные крошки (BreadcrumbList), готовая разметка в `#root`.
- Главная дополнительно: Organization, WebSite, WebApplication с ценами пакетов кредитов и FAQPage из `features/content/faq.ts`.
- `/docs/plans/*` дублируют `/docs`, поэтому их canonical — `/docs`, в sitemap их нет.
- Разделы приложения (`/chat`, `/settings`, `/checkout`…): `noindex, nofollow`, закрыты в robots.txt.
- Несуществующие адреса — 404.
- Дубли адресов: `/pricing/` (со слэшем) → 301 на `/pricing`, `/index.html` → 301 на `/`. Закрытые разделы со слэшем не перенаправляются.
- `/favicon.ico` лежит в `apps/web/public` (PNG 128×128 внутри ICO): Яндекс и часть роботов запрашивают его по умолчанию, хотя страницы ссылаются на `/favicon.png`.
- Запросы на `ketner-ai.onrender.com` (любой хост, кроме ketner.org и www) получают `X-Robots-Tag: noindex`, чтобы в выдаче не было копии сайта. `www` и `http` уже перенаправляются на `https://ketner.org` (301).

**robots.txt.** Общий блок и отдельный блок для Яндекса с `Clean-param` для меток (`utm_*`, `gclid`, `yclid`, `fbclid`, `ysclid`, `from`): адреса с метками Яндекс склеивает с основным.

**sitemap.xml.** Все страницы из `seo-pages.json`, кроме помеченных `"sitemap": false`. `lastmod` пишется только там, где известна настоящая дата изменения: `/changelog` (последний выпуск) и правовые страницы (дата редакции). Даты считает `PAGE_LASTMODS` в `entry-prerender.tsx` при сборке и кладёт в `dist/.prerender.json`. У остальных страниц `lastmod` нет: дата сборки одинакова для всех адресов, и поисковики перестают ей верить. Появилась страница с датой изменения — добавьте её в `PAGE_LASTMODS`.

## Как добавить страницу

1. Маршрут в `apps/web/src/router/routes.tsx` (внутри `StandaloneLayout`).
2. Запись в `apps/mock-api/src/seo/seo-pages.json`: `path`, короткое `name`, `title` (до 75 символов, ключевая фраза в начале), `description` (до 250 символов, отвечает на вопрос «что здесь есть»), `priority`, `changefreq`.
3. На странице один `<h1>`. Свой `useDocumentTitle` не нужен: заголовок ставит раскладка.
4. `npm run build` — страница отрисуется и попадёт в sitemap.

## Что сделать владельцу

1. **Google Search Console.** Добавить ресурс «Домен» `ketner.org` (подтверждение TXT-записью в Cloudflare) или «Префикс URL» с переменной `GOOGLE_SITE_VERIFICATION` на Render. Отправить `https://ketner.org/sitemap.xml`. Проверить главную в «Проверке URL» и запросить индексирование главной, `/pricing`, `/models`, `/docs`.
2. **Яндекс Вебмастер.** Добавить сайт, подтвердить метатегом (`YANDEX_VERIFICATION` на Render), отправить sitemap, в «Переобходе страниц» отправить главные страницы. В «Региональности» указать регион, если аудитория в одной стране.
3. **Bing Webmaster Tools** (необязательно): импорт из Search Console в один клик.
4. **Хостинг.** Бесплатный Render засыпает: первый запрос после простоя ждёт запуска. Робот, получивший таймаут, приходит реже. Платный план (roadmap) нужен и для SEO.
5. Через 1–2 недели после подтверждения смотреть в обоих кабинетах: проиндексированные страницы, ошибки, запросы, по которым показывается сайт.

## Что дальше по содержанию

Техническая часть закрыта; дальше трафик даёт текст под конкретные запросы. По частоте в русскоязычном поиске:

- **Страницы моделей** (`/models/claude-opus-5-5` и т. п.): что умеет модель, кто разработал, с какой ценой запроса в кредитах, пример запроса. Запросы вида «Claude Opus на русском», «GPT-6 онлайн».
- **Сценарии**: «нейросеть для учёбы / текстов / кода», «генерация картинок онлайн» (`/images` как открытая витрина с примерами).
- **Сравнения**: «ChatGPT или Claude», «Ketner или подписка ChatGPT Plus» — калькулятор с главной уже есть, его можно вынести отдельной страницей.
- **Справка** по частым вопросам (оплата звёздами, крипта, API для Cursor) — отдельные статьи вместо одной длинной страницы.

Утверждения о доступности (например, «без VPN» в конкретной стране) писать только после проверки.
