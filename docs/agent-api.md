# Ketner Agent API (контракт)

Документ описывает HTTP-контракт между сервером Ketner AI и клиентами для программирования: IDE (Cursor,
Continue, Cline) и любыми OpenAI-совместимыми программами. Собственного CLI-агента `ketner` в репозитории пока нет:
контракт рассчитан на него, но клиент не написан.
Сервер ничего не исполняет у пользователя: цикл «модель → инструмент → результат» крутит клиент на
компьютере пользователя, а сервер проверяет доступ и кредиты, выбирает модель, ведёт учёт расходов и
пересылает запросы в OpenRouter единым ключом.

## Аутентификация

`Authorization: Bearer ketner_sk_<64 hex>`. Ключ создаётся в разделе API на сайте и показывается один раз;
сервер хранит только его SHA-256. Ключ действует от имени владельца: уровень доступа, кредиты и технические лимиты те же, что в чате: запросы по ключу списывают кредиты из общего пула тарифа.
Создать ключ и вызвать `/v1/chat/completions` можно после покупки кредитов (пока купленные кредиты не потрачены; на одних пробных 200 кредитах API закрыт: 403 `upgrade_required`; прежним подписчикам Plus и выше доступ сохраняется до конца срока). `GET /v1/models` и `GET /v1/usage` отвечают
любому действующему ключу. Ключ можно отозвать в любой момент. Токен сессии сайта вместо ключа не принимается.

Базовый адрес: `<адрес сайта>/v1`.

Каждый ответ `/v1` несёт заголовок `X-Request-Id: req_<24 hex>`: его стоит логировать и называть поддержке.
CORS для `/v1` открыт любому сайту (`Access-Control-Allow-Origin: *`, без cookie, заголовки из preflight
разрешаются, `X-Request-Id` и `Retry-After` читаемы). Авторизация там только ключом, поэтому чужая страница
может лишь то, что даёт ей сам ключ; ключ в публичном фронтенде увидит любой посетитель, так что из браузера
API годится для прототипов, расширений и внутренних инструментов. API сайта (`/api/*`) по-прежнему закрыт
для чужих адресов.

## Эндпоинты

### `GET /v1/models`

```json
{
  "object": "list",
  "data": [
    {
      "id": "ketner-pro",
      "object": "model",
      "created": 1760000000,
      "owned_by": "ketner",
      "name": "Ketner Pro",
      "context_window": 1050000,
      "max_output_tokens": 131072,
      "cost_class": "work",
      "requires_plan": "credits",
      "available": true
    }
  ]
}
```

`GET /v1/models/{id}` возвращает одну модель в том же виде (для `client.models.retrieve`), неизвестный id —
404 `model_not_found`.

Возвращает `auto` и все публичные модели каталога; `available` говорит, доступна ли модель владельцу ключа (все модели каталога открыты), `requires_plan` для API у всех моделей равен `credits` (нужны купленные кредиты). `auto` сейчас всегда ведёт на `ketner-pro`.
Модель агента по умолчанию — `ketner-pro`. Каждый запрос списывает кредиты по реальной цене модели (1 кредит = $0.001), поэтому дорогие модели (`cost_class` `strong` и `top`) расходуют их быстрее; цены моделей в кредитах — в `GET /api/usage/credits` (сайт) и в `docs/models-and-pricing.md`.

### `POST /v1/chat/completions`

Формат OpenAI Chat Completions (текст и вызов функций). Принимаются поля:

| Поле                                    | Описание                                                                                                                                                                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`                                 | id из `/v1/models` или `auto`                                                                                                                                                                                                             |
| `messages`                              | роли `system`, `user`, `assistant` (с `tool_calls`), `tool` (с `tool_call_id`); `content` — строка либо массив `{type:"text", text}`                                                                                                      |
| `tools`                                 | до 64 функций `{type:"function", function:{name, description, parameters}}`                                                                                                                                                               |
| `tool_choice`                           | `auto`, `none`, `required` или `{type:"function", function:{name}}`                                                                                                                                                                       |
| `stream`                                | `true` — SSE `data: {...}` и в конце `data: [DONE]`                                                                                                                                                                                       |
| `stream_options`                        | `{include_usage: true}` — перед `[DONE]` отдельный кусок с `choices: []`, `usage` и `ketner`, как у OpenAI; без него расход приходит в куске с `finish_reason`                                                                            |
| `max_tokens`, `max_completion_tokens`   | потолок ответа; сервер ограничивает его уровнем: вдвое выше чатового (32768 токенов при купленных кредитах), но не выше предела модели; в экономном режиме бюджета ещё ниже                                                               |
| `temperature`                           | 0–2                                                                                                                                                                                                                                       |
| `top_p`                                 | 0–1                                                                                                                                                                                                                                       |
| `stop`                                  | строка или до 4 строк по 1–256 символов                                                                                                                                                                                                   |
| `seed`                                  | целое число; повторяемость зависит от модели                                                                                                                                                                                              |
| `frequency_penalty`, `presence_penalty` | −2…2                                                                                                                                                                                                                                      |
| `response_format`                       | `{type:"text"}`, `{type:"json_object"}` или `{type:"json_schema", json_schema:{name, schema, strict}}` (structured outputs); поддержка зависит от модели                                                                                  |
| `user`                                  | строка, принимается и игнорируется                                                                                                                                                                                                        |
| `reasoning_effort`                      | `none`, `minimal`, `low`, `medium`, `high`; по умолчанию `low`. Сервер ограничивает глубину: `high` доступен при купленных кредитах (у прежних подписчиков Plus и Pro не выше `medium`), на подходе бюджета к пределу (80%) не выше `low` |

Параметры из таблицы передаются модели без изменений; неверное значение — 400 с `error.param`. Не поддерживается:
`n` больше 1 (ошибка), картинки и аудио в `content` (ошибка), `logprobs`, `logit_bias`, `parallel_tool_calls` и прочие
параметры OpenAI (молча игнорируются). Последнее сообщение должно быть от `user` или `tool`.
`tool_call_id` в сообщении `tool` должен совпадать с вызовом из предыдущего сообщения `assistant`.
Сервер не добавляет собственных системных инструкций: роль и правила агента задаёт клиент.

Ответ без стриминга:

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "created": 1760000000,
  "model": "ketner-pro",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_1",
            "type": "function",
            "function": { "name": "read_file", "arguments": "{\"path\":\"src/a.ts\"}" }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ],
  "usage": {
    "prompt_tokens": 1200,
    "completion_tokens": 80,
    "total_tokens": 1280,
    "prompt_tokens_details": { "cached_tokens": 900 }
  },
  "ketner": {
    "cost_usd": 0.0012,
    "requested_model": "gpt-6.1-sol",
    "routing_reason": "Not enough credits for GPT-6.1 Sol: Ketner Pro answers instead",
    "credits": { "charged": 1.2, "balance": 8450, "stage": "normal" }
  }
}
```

Поле `model` — модель, которая реально ответила (если кредитов на запрошенную модель не хватает, сервер подставляет более дешёвую, а когда они кончились, бесплатную модель агента, и пишет причину в `ketner.routing_reason`). `ketner.credits`: `charged` — сколько кредитов списал этот запрос (0 у бесплатной модели), `balance` — остаток после списания, `stage` — `normal` или `exhausted` (кредитов нет, отвечает бесплатная модель). `finish_reason`: `stop`, `length`, `tool_calls`. `length` значит, что ответ неполон (упёрся в потолок, оборвался по таймауту
или связь с моделью прервалась): аргументы последнего вызова функции могут быть обрезаны, клиент обязан проверить
их как JSON, прежде чем исполнять.

Потоковый ответ: куски `chat.completion.chunk` с `choices[0].delta` (первый с `role`, дальше `content`,
`reasoning_content`, `tool_calls` с `index`, `id`, `function.name`, `function.arguments` по частям). Затем кусок
с `finish_reason`, в котором уже лежат `usage` и `ketner`, и `data: [DONE]`. У каждого куска ровно один элемент
`choices`, так что `chunk.choices[0]` безопасен. С `stream_options.include_usage: true` перед `[DONE]` идёт ещё
кусок с `choices: []`, `usage` и `ketner`. Пока модель думает дольше 10 секунд,
сервер шлёт комментарии `: keepalive`, чтобы прокси не разорвал соединение.

Если связь с моделью оборвалась уже после начала ответа, приходит `data: {"error": {...}}` (официальные SDK
поднимают на нём исключение), затем кусок с `usage` (только при `include_usage`) и `[DONE]`, а куска с
`finish_reason` нет: клиент знает, что ответ неполон. Запасная модель после первого
отправленного фрагмента не включается, чтобы не склеить два разных ответа. Ошибка до первого фрагмента
(лимиты, недоступность моделей) приходит обычным HTTP-статусом и JSON, даже при `stream: true`.

Запрос без `stream` держит соединение до конца генерации; через прокси длинные задачи надёжнее вести потоком.

### `GET /v1/usage`

```json
{
  "plan": "credits",
  "credits": {
    "balance": 9800,
    "stage": "normal",
    "next_expires_at": "2027-10-26T10:00:00.000Z",
    "next_expiring": 2400
  },
  "requests_last_day": 42
}
```

`plan` — уровень доступа (`credits` у покупателя с неистраченными купленными кредитами, `free` без них, у прежних подписчиков — их тариф), `balance` — остаток кредитов, `next_expires_at` и `next_expiring` — когда сгорает ближайший грант кредитов и сколько в нём. `stage`: `normal` или `exhausted` (кредитов нет: отвечает бесплатная модель, платные модели вернутся после покупки пакета).

## Ошибки

Тело `{"error": {"message": "...", "type": "...", "code": "..."}}`.

| HTTP | `code`                    | Когда                                                                            |
| ---- | ------------------------- | -------------------------------------------------------------------------------- |
| 400  | `invalid_request_error`   | неверное тело запроса                                                            |
| 400  | `context_length_exceeded` | история не помещается в окно модели: клиент должен сжать контекст                |
| 401  | `invalid_api_key`         | нет ключа, ключ неверный или отозван                                             |
| 403  | `upgrade_required`        | нет купленных кредитов: API закрыт на уровне Free (пробные кредиты)              |
| 404  | `model_not_found`         | модели нет среди публичных (список: `GET /v1/models`; старые id не принимаются)  |
| 413  | `request_too_large`       | тело больше 8 МБ                                                                 |
| 429  | `rate_limit_exceeded`     | лимит запросов или параллельных запросов; есть `Retry-After` (секунды, примерно) |
| 400  | `invalid_request_error`   | провайдер отклонил запрос (текст причины в `message`)                            |
| 500  | `internal_error`          | внутренняя ошибка сервера                                                        |
| 502  | `upstream_error`          | все модели цепочки недоступны                                                    |
| 503  | `provider_unavailable`    | на стороне сервера недоступен ключ OpenRouter или пуст его баланс                |

`error.type` по OpenAI: `invalid_request_error`, `authentication_error`, `permission_error`, `not_found_error`,
`rate_limit_error`, `server_error`. `error.param` указывает на неверное поле запроса.

## Ключи API (для сайта; авторизация сессией)

| Метод  | Путь                                | Ответ                                                                                 |
| ------ | ----------------------------------- | ------------------------------------------------------------------------------------- |
| GET    | `/api/keys`                         | `{ "keys": [{ "id", "name", "prefix", "createdAt", "lastUsedAt" }] }`                 |
| POST   | `/api/keys` `{ "name": "MacBook" }` | `{ "key": { ...как выше }, "secret": "ketner_sk_..." }`: секрет показывается один раз |
| DELETE | `/api/keys/:id`                     | `{ "ok": true }`                                                                      |

Ошибки этих эндпоинтов в формате сайта `{ "error": { "code", "message" } }`: 401 без сессии, 403 `upgrade_required`
(создание ключа возможно после покупки кредитов), 400 `invalid_request` (нет имени или оно не 1–60 символов), 409 `key_limit_reached`
(уже 10 действующих), 404 `not_found` (ключ чужой или уже отозван).

До 10 действующих ключей на пользователя; имя 1–60 символов. `prefix` — первые 14 символов ключа для опознания.
Ключами управляет только сессия сайта: API-ключом создать или отозвать ключ нельзя.

## Учёт и лимиты

- Каждый шаг агента — отдельный запрос и отдельная запись расхода (диалог `api:<id ключа>`); считается по
  фактической цене OpenRouter и списывает кредиты из того же пула, что и чат.
- Если запрошенная модель заменена (не хватает кредитов, модель недоступна), расход пишется
  по модели, которая ответила, а причина замены лежит в `ketner.routing_reason`. Клиент обязан показывать её пользователю.
- Лимиты запросов в минуту, час и день действуют как в чате. Лимит токенов в час и в сутки для API не
  применяется (контекст агента растёт с каждым шагом). Расход ограничивают только кредиты, общие с чатом,
  картинками и Ketner Code. Когда они кончаются, запросы не отклоняются: отвечает бесплатная модель агента
  (North Mini Code), `ketner.credits.stage` становится `exhausted`, а модель в ответе показывает, кто ответил.
- Стоимость задачи агента на порядок выше стоимости сообщения в чате. Ориентир для `ketner-pro`: 15 шагов
  со средним контекстом 25k токенов ≈ $0.15–0.30 (150–300 кредитов); для `gpt-6.1-sol` ≈ $0.5–1 (500–1000); для `claude-opus-5.5` ≈ $1.5–2 (1500–2000).
