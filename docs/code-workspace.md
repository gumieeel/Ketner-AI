# Ketner Code: проекты и ИИ-агент

Ketner Code — раздел `/code`: серверные проекты с файлами и агент, который читает код, правит его и (на платных тарифах) запускает тесты. Устройство и план доработок до «полноценной системы» — ниже.

## Что уже есть

| Блок                | Где                                                        | Что делает                                                                                                                                                     |
| ------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Хранилище проектов  | `apps/mock-api/src/code/project-store.ts`, `project-fs.ts` | Рабочая копия на диске (`CODE_PROJECTS_DIR`), защита путей и симлинков, запрет записи в `.git`, секретные файлы скрыты от агента                               |
| Постоянное хранение | `code/postgres-driver.ts`                                  | Таблицы `code_projects`, `code_project_files`; диск — рабочая копия, при первом обращении проект поднимается из БД                                             |

### Лимиты по тарифам

|                         | Free  | Plus  | Pro   | Ultra  |
| ----------------------- | ----- | ----- | ----- | ------ |
| Проектов                | 1     | 5     | 20    | 100    |
| Файлов в проекте        | 200   | 1 000 | 3 000 | 10 000 |
| Размер проекта          | 1 МБ  | 10 МБ | 25 МБ | 100 МБ |
| Запусков агента в сутки | 3     | 15    | 40    | 120    |
| Шагов за запуск         | 8     | 25    | 50    | 100    |
| Бюджет запуска          | $0,02 | $0,10 | $2,00 | $3,00  |
| Запуск команд           | нет   | нет   | да    | да     |

Бюджет запуска дополнительно ограничивается остатком суточного и месячного бюджета тарифа и остатком премиум-квоты, так что агент не может «съесть» больше, чем заложено в тариф.

Сколько стоит задача агенту (15 шагов по ~20k токенов контекста, половина из кэша / крупная — 25 шагов по ~35k):

| Модель                              | Типичная   | Типичная, Max | Крупная    | Крупная, Max |
| ----------------------------------- | ---------- | ------------- | ---------- | ------------ |
| Claude Sonnet 5.5, GPT-5.6 Sol      | $0.38–0.39 | $0.46–0.48    | $0.87–0.93 | $1.05–1.10   |
| Grok 4.7 xhigh, GPT-5.6 Terra xhigh | $0.46–0.51 | так же        | $1.14–1.17 | так же       |
| Claude Opus 5.5                     | $0.75      | $0.93         | $1.74      | $2.10        |
| GPT-6 Astra                         | $1.95      | $2.40         | $4.6       | $5.5         |

Бюджет Pro ($2) покрывает типичную задачу на любой модели и крупную на Opus и дешевле; Ultra ($3) — типичную в режиме Max и крупную на Opus в режиме Max. Крупные задачи на Astra доделываются на моделях дешевле, сделанное сохраняется. Чтобы запуск не упирался в дневной потолок тарифа, он поднят до $2.20 (Pro) и $4.40 (Ultra); месячный бюджет прежний. Запуск агента считается одним использованием в суточном лимите модели (в режиме Max — двумя).

### Как идёт запуск

1. `POST /api/code/projects/:id/run` с задачей, моделью (`auto` или конкретная) и языком. Ответ — поток SSE.
2. Сервер проверяет тариф, суточный лимит запусков и бюджет; отклонённый запуск возвращает событие `error` и в ленту не пишется.
3. Модель получает системную инструкцию, историю прошлых реплик проекта (только тексты пользователя и ассистента) и набор инструментов. Каждый шаг: ответ модели → вызовы инструментов → результаты → следующий шаг.
4. События: `run_start`, `model_switch`, `delta`, `tool_call`, `tool_result` (с патчем изменения), `plan`, `step_done`, `done` / `error`.
5. Лента (инструменты, правки, итог) сохраняется в проекте и подгружается при открытии.

### Работа по плану (как в Claude Code)

- Если задача больше одной-двух правок, агент первым шагом изучает проект и вызывает `update_plan`: 3–8 конкретных подзадач по порядку.
- Подзадачи выполняются по одной: ровно одна «в работе» (сервер следит за этим), после проверки она отмечается выполненной, и в том же вызове в работу ставится следующая. Ответ инструмента сообщает модели текущий и следующий пункт.
- Если модель решила закончить, а в плане остались пункты, сервер напоминает про них (не больше двух раз за запуск, чтобы не зациклиться на невыполнимом пункте).
- В интерфейсе план — закреплённый список «Задачи» в верхней части панели агента (справа), с прогрессом «2 из 4» и текущим пунктом; в шапке проекта — компактный индикатор `2/4` (на телефоне он открывает вкладку «Агент»). План сохраняется в записи о завершении запуска (`plan` в ленте и в событии `done`), поэтому виден и после перезагрузки.

### Лимит закончился — работа продолжается на модели дешевле

Запуск идёт ступенями. Ступень 0 — выбранная модель с бюджетом тарифа на запуск (Pro $2, Ultra $3, Plus $0.10, Free $0.02; не больше остатка дня, месяца и квоты премиум-моделей). Когда бюджет ступени или лимит шагов исчерпан, агент **не останавливается**: он молча переходит на модель дешевле и продолжает с текущего пункта плана.

| Ступень | Модель                                                             | Добавочный бюджет (Free / Plus / Pro / Ultra) |
| ------- | ------------------------------------------------------------------ | --------------------------------------------- |
| Рабочая | первая модель класса work в цепочке запасных (обычно Ketner Pro)   | — / $0.10 / $0.40 / $0.60                     |
| Лёгкая  | первая модель класса lite (Haiku 5.5, GPT-6 Luna Pro, Ketner Mini) | $0.01 / $0.05 / $0.10 / $0.15                 |

- Каждая ступень даёт ещё половину лимита шагов; всего не больше двойного лимита шагов тарифа.
- Модель получает служебную заметку с текущим планом, пользователь видит только новую модель в шапке панели — без ошибок и остановки.
- Общий потолок запуска: остаток месячного бюджета (125%) и дневной потолок тарифа с запасом 25%. Только когда исчерпаны и ступени дешевле, запуск завершается со статусом «Достигнут лимит запуска»; сделанные правки сохраняются.
- Если бюджет выбранной модели закончился ещё до старта (например, дневной расход), запуск сразу начинается на ступени дешевле, а не отклоняется.

### Безопасность

- Пути нормализуются, выход за корень проекта и запись через симлинк запрещены; `.git` для записи закрыт.
- Файлы с секретами (`.env`, ключи, сертификаты) не показываются агенту и пропускаются при импорте.
- ZIP: проверка заявленных размеров до распаковки (защита от zip-бомб), лимиты числа и размера файлов.
- GitHub: только хост `github.com`; приватные репозитории — токеном подключённого аккаунта (хранится на сервере зашифрованным, см. [auth-and-security.md](auth-and-security.md)).
- Файл инструкций проекта (`KETNER.md`, `AGENTS.md` или `CLAUDE.md` в корне) подмешивается в системную инструкцию агента.
- `search_files`: защита от катастрофических регулярных выражений.
- Команды: по умолчанию выключены. Режим `local` в production заблокирован, пока явно не задано `SANDBOX_ALLOW_LOCAL_IN_PRODUCTION=true`. Docker-режим запускает контейнер с `--network none`, лимитами памяти и процессов.

## Что ещё нужно для полноценной системы

Ниже — честный список: что не сделано или не проверено вживую, в порядке важности.

### Обязательно до открытия для всех

1. **Живая проверка с OpenRouter.** Вызов инструментов покрыт тестами на подставных ответах. Нужно прогнать реальные запуски на каждой модели из каталога: не все модели OpenRouter поддерживают tool calling. Сервер умеет переключаться на запасную модель, но список «годных для агента» моделей стоит зафиксировать по результатам проверки.
2. **Изолированный запуск команд.** `DockerSandbox` написан по канонам (`--network none`, лимиты, нет привилегий), но вживую не проверен. Для продакшена лучше отдельный воркер (отдельная машина или gVisor/Firecracker), а не Docker на хосте с API. До этого `SANDBOX_MODE=off` — агент правит файлы, но тесты не запускает.
3. **Долговечность на Render.** Диск Render эфемерный: проекты и учёт использования переживают деплой только через Postgres (`DATABASE_URL`) — проекты в `code_projects`, учёт в `ketner_docs`. Без базы счётчики лимитов сбрасываются при перезапуске.
4. **Защита от злоупотреблений.** Лимиты по пользователю и по IP на вход и регистрацию есть, но нужны: лимит одновременных запусков на сервер, дневной потолок расходов на весь сервис, алерт при всплеске расходов, блокировка аккаунта из админки.
5. **Платежи.** Тарифы оплачиваются криптой (Trybit, пока в тестовом режиме) и звёздами; оплаты картой нет ([payments.md](payments.md)).

### Для уровня Codex / Claude Code

6. **Git внутри проекта.** Сейчас `.git` закрыт. Нужны: история изменений и откат шага агента, ветки, коммит и push в GitHub, создание pull request. Привязка аккаунта GitHub и коммит или PR через прокси уже есть в чате («Применить к GitHub») — их можно переиспользовать.
7. **Откат и просмотр изменений запуска.** Агент показывает патч каждой правки, но нет кнопки «отменить весь запуск» и общего diff по всем файлам. Решается снимком файлов перед запуском.
8. **Предпросмотр.** Для статических сайтов — iframe с раздачей файлов проекта; для приложений — отдельный воркер с проксированием порта.
9. **Редактор уровня IDE.** Сейчас textarea с номерами строк. Заменить на CodeMirror 6 (подсветка, поиск, сворачивание, автодополнение по файлам проекта, несколько курсоров), добавить поиск по проекту и палитру команд.
10. **Терминал.** Живой вывод команд по потоку и интерактивный терминал (WebSocket + PTY в воркере). Сейчас агент видит только итог команды.
11. **Контекст и память.** Файл инструкций проекта уже подмешивается; не хватает индекса проекта для поиска по смыслу и сжатия длинной истории.
12. **Параллельные и фоновые задачи.** Несколько агентов на проект, запуск по расписанию, уведомления о завершении, продолжение запуска после обрыва соединения (сейчас запуск привязан к SSE-соединению).
13. **Совместная работа.** Общий доступ к проекту по ссылке, роли, комментарии к правкам.
14. **Экспорт в GitHub.** Импорт приватных репозиториев работает; выгрузки изменений проекта обратно в репозиторий нет.
15. **Подсказки в строке (автодополнение)** отдельной быстрой моделью.

### Эксплуатация

16. **Наблюдаемость.** Метрики: запуски, шаги, стоимость, доля ошибок по моделям, время до первого токена; трассировка запуска; страница в админке с самыми дорогими пользователями и запусками.
17. **Резервное копирование** БД с проектами и проверка восстановления.
18. **Тесты в браузере (E2E).** Сквозной сценарий: создать проект → запустить агента → увидеть правку → скачать ZIP.
19. **Юридическое.** Условия использования для кода пользователей, срок хранения, удаление проектов при удалении аккаунта.
