# Ketner Code: проекты и ИИ-агент

Ketner Code — раздел `/code`: серверные проекты с файлами и агент, который читает код, правит его и (на платных тарифах) запускает тесты. Устройство и план доработок до «полноценной системы» — ниже.

## Что уже есть

| Блок | Где | Что делает |
|---|---|---|
| Хранилище проектов | `apps/mock-api/src/code/project-store.ts`, `project-fs.ts` | Рабочая копия на диске (`CODE_PROJECTS_DIR`), защита путей и симлинков, запрет записи в `.git`, секретные файлы скрыты от агента |
| Постоянное хранение | `code/postgres-driver.ts` | Таблицы `code_projects`, `code_project_files`; диск — рабочая копия, при первом обращении проект поднимается из БД |
| Создание и импорт | `routes/code.ts`, `code/archive.ts`, `code/templates.ts` | Пустой проект, шаблоны (`node`, `python`, `web`), загрузка папки и ZIP (в браузере), публичный репозиторий GitHub, выгрузка ZIP |
| Инструменты агента | `code/agent-tools.ts` | `list_files`, `read_file`, `search_files`, `edit_file`, `write_file`, `move_file`, `delete_file`, `update_plan`, `run_command` (если включена песочница) |
| Цикл агента | `code/agent-runner.ts` | Много шагов модели за один запрос (SSE), лимиты шагов и стоимости, смена модели при сбое, отмена, учёт в `usage-store` |
| Песочница команд | `code/sandbox.ts` | `SANDBOX_MODE=off` (по умолчанию) · `docker` · `local` (только разработка) |
| Лимиты тарифов | `services/code-limits.ts` | Проекты, файлы, размер, запусков в сутки, шаги, бюджет запуска, команды |
| Экран | `apps/web/src/pages/code-page.tsx`, `components/code/*` | Список проектов и импорт, дерево файлов, редактор, лента агента с diff, «Стоп» |

### Лимиты по тарифам

| | Free | Plus | Pro | Ultra |
|---|---|---|---|---|
| Проектов | 1 | 5 | 20 | 100 |
| Файлов в проекте | 200 | 1 000 | 3 000 | 10 000 |
| Размер проекта | 1 МБ | 10 МБ | 25 МБ | 100 МБ |
| Запусков агента в сутки | 3 | 15 | 40 | 120 |
| Шагов за запуск | 8 | 25 | 50 | 100 |
| Бюджет запуска | $0,02 | $0,10 | $2,00 | $3,00 |
| Запуск команд | нет | нет | да | да |

Бюджет запуска дополнительно ограничивается остатком суточного и месячного бюджета тарифа и остатком премиум-квоты, так что агент не может «съесть» больше, чем заложено в тариф.

Сколько стоит задача агенту (15 шагов по ~20k токенов контекста, половина из кэша / крупная — 25 шагов по ~35k):

| Модель | Типичная | Типичная, Max | Крупная | Крупная, Max |
|---|---|---|---|---|
| Claude Sonnet 5.5, GPT-5.6 Sol | $0.38–0.39 | $0.46–0.48 | $0.87–0.93 | $1.05–1.10 |
| Grok 4.7 xhigh, GPT-5.6 Terra xhigh | $0.46–0.51 | так же | $1.14–1.17 | так же |
| Claude Opus 5.5 | $0.75 | $0.93 | $1.74 | $2.10 |
| Claude Fable 5.1, GPT-6 Astra | $1.84–1.95 | $2.29–2.40 | $4.2–4.6 | $5.1–5.5 |

Бюджет Pro ($2) покрывает типичную задачу на любой модели и крупную на Opus и дешевле; Ultra ($3) — типичную в режиме Max и крупную на Opus в режиме Max. Крупные задачи на Fable и Astra обрываются по бюджету, сделанное сохраняется. Чтобы запуск не упирался в дневной потолок тарифа, он поднят до $2.20 (Pro) и $4.40 (Ultra); месячный бюджет прежний. Запуск агента считается одним использованием в суточном лимите модели (в режиме Max — двумя).

### Как идёт запуск

1. `POST /api/code/projects/:id/run` с задачей, моделью (`auto` или конкретная) и языком. Ответ — поток SSE.
2. Сервер проверяет тариф, суточный лимит запусков и бюджет; отклонённый запуск возвращает событие `error` и в ленту не пишется.
3. Модель получает системную инструкцию, историю прошлых реплик проекта (только тексты пользователя и ассистента) и набор инструментов. Каждый шаг: ответ модели → вызовы инструментов → результаты → следующий шаг.
4. События: `run_start`, `model_switch`, `delta`, `tool_call`, `tool_result` (с патчем изменения), `plan`, `step_done`, `done` / `error`.
5. Лента (инструменты, правки, итог) сохраняется в проекте и подгружается при открытии.

### Безопасность

- Пути нормализуются, выход за корень проекта и запись через симлинк запрещены; `.git` для записи закрыт.
- Файлы с секретами (`.env`, ключи, сертификаты) не показываются агенту и пропускаются при импорте.
- ZIP: проверка заявленных размеров до распаковки (защита от zip-бомб), лимиты числа и размера файлов.
- GitHub: только хост `github.com` и публичные репозитории.
- `search_files`: защита от катастрофических регулярных выражений.
- Команды: по умолчанию выключены. Режим `local` в production заблокирован, пока явно не задано `SANDBOX_ALLOW_LOCAL_IN_PRODUCTION=true`. Docker-режим запускает контейнер с `--network none`, лимитами памяти и процессов.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `CODE_PROJECTS_DIR` | Каталог рабочих копий проектов | `apps/mock-api/data/projects` |
| `SANDBOX_MODE` | `off` · `docker` · `local` | `off` |
| `SANDBOX_DOCKER_IMAGE` | Образ для `docker`-режима | `node:22-bookworm` |
| `SANDBOX_ALLOW_NETWORK` | Разрешить сеть внутри команд (`npm install`) | `false` |
| `SANDBOX_ALLOW_LOCAL_IN_PRODUCTION` | Разрешить `local` в production (небезопасно) | `false` |

## Что ещё нужно для полноценной системы

Ниже — честный список: что не сделано или не проверено вживую, в порядке важности.

### Обязательно до открытия для всех

1. **Живая проверка с OpenRouter.** Вызов инструментов покрыт тестами на подставных ответах. Нужно прогнать реальные запуски на каждой модели из каталога: не все модели OpenRouter поддерживают tool calling. Сервер умеет переключаться на запасную модель, но список «годных для агента» моделей стоит зафиксировать по результатам проверки.
2. **Изолированный запуск команд.** `DockerSandbox` написан по канонам (`--network none`, лимиты, нет привилегий), но вживую не проверен. Для продакшена лучше отдельный воркер (отдельная машина или gVisor/Firecracker), а не Docker на хосте с API. До этого `SANDBOX_MODE=off` — агент правит файлы, но тесты не запускает.
3. **Долговечность на Render.** Диск Render эфемерный: проекты переживают рестарт только через PostgreSQL-драйвер (включается с `DATABASE_URL`). Файл `usage.json` с учётом использования тоже на диске — без БД счётчики лимитов сбрасываются при перезапуске, то есть лимиты можно обойти. Нужно перенести учёт использования в Postgres.
4. **Защита от злоупотреблений.** Лимиты по пользователю есть, но нужны: ограничение частоты запросов по IP, лимит одновременных запусков на сервер, дневной потолок расходов на весь сервис, алерт при всплеске расходов, блокировка аккаунта из админки.
5. **Формулировка «безлимит».** Лимиты запусков и бюджет запуска делают «безлимит» неточным. На страницах тарифов и в документации заменить на «щедрые лимиты / Fair Use» с конкретными числами.
6. **Платежи.** Цены `$0 / $9 / $25 / $49` совпадают с кодом, но в Stripe нужны реальные Price ID (`STRIPE_PRICE_*`), а для Telegram Stars — пересчитанные цены. Без этого платных пользователей не будет.

### Для уровня Codex / Claude Code

7. **Git внутри проекта.** Сейчас `.git` закрыт. Нужны: история изменений и откат шага агента, ветки, коммит и push в GitHub (через OAuth-приложение, токен хранить зашифрованным), создание pull request.
8. **Откат и просмотр изменений запуска.** Агент показывает патч каждой правки, но нет кнопки «отменить весь запуск» и общего diff по всем файлам. Решается снимком файлов перед запуском.
9. **Предпросмотр.** Для статических сайтов — iframe с раздачей файлов проекта; для приложений — отдельный воркер с проксированием порта.
10. **Редактор уровня IDE.** Сейчас textarea с номерами строк. Заменить на CodeMirror 6 (подсветка, поиск, сворачивание, автодополнение по файлам проекта, несколько курсоров), добавить поиск по проекту и палитру команд.
11. **Терминал.** Живой вывод команд по потоку и интерактивный терминал (WebSocket + PTY в воркере). Сейчас агент видит только итог команды.
12. **Контекст и память.** Файл инструкций проекта (`KETNER.md` / `AGENTS.md`), который подмешивается в системную инструкцию; индекс проекта для быстрого поиска по смыслу; сжатие длинной истории.
13. **Параллельные и фоновые задачи.** Несколько агентов на проект, запуск по расписанию, уведомления о завершении, продолжение запуска после обрыва соединения (сейчас запуск привязан к SSE-соединению).
14. **Совместная работа.** Общий доступ к проекту по ссылке, роли, комментарии к правкам.
15. **Импорт приватных репозиториев** через GitHub App и экспорт обратно.
16. **Подсказки в строке (автодополнение)** отдельной быстрой моделью.

### Эксплуатация

17. **Наблюдаемость.** Метрики: запуски, шаги, стоимость, доля ошибок по моделям, время до первого токена; трассировка запуска; страница в админке с самыми дорогими пользователями и запусками.
18. **Резервное копирование** БД с проектами и проверка восстановления.
19. **Тесты в браузере (E2E).** Сквозной сценарий: создать проект → запустить агента → увидеть правку → скачать ZIP.
20. **Юридическое.** Условия использования для кода пользователей, срок хранения, удаление проектов при удалении аккаунта.
