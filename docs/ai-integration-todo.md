# Подключение реального ИИ

Что заменить, когда появится настоящая модель. Документ — чек-лист: пункты выполняются по мере перехода от заглушки к провайдеру.

## Что есть сейчас (этап 2)

- `apps/mock-api/src/routes/chat.ts` — эндпоинт `POST /api/chat/completions`, отдаёт ответ потоком через SSE.
- Ответ собирается из заранее заданных шаблонов: выбор зависит от ключевых слов в запросе, иначе берётся случайный.
- Чанки отправляются с задержкой 20-40 мс, чтобы фронтенд работал со стримингом так же, как с реальным провайдером.
- Переключатель моделей меняет только подпись в интерфейсе; логика ответа одна.
- Сервер получает историю целиком и заменяет ею сохранённую: на этом держатся правка сообщения, повторная генерация и остановка.
- При остановке генерации частичный ответ сохраняется в диалоге со статусом `complete`.
- `usage` с числом токенов уже приходит в событии `done` (сейчас — оценка по длине текста).

## Контракт, который нельзя ломать

Запрос:

```http
POST /api/chat/completions
Content-Type: application/json

{
  "conversationId": "uuid",
  "modelId": "ketner-mini",
  "language": "ru",
  "messages": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}
```

Ответ — `text/event-stream` со событиями:

```
event: delta
data: {"content":"порция текста"}

event: done
data: {"messageId":"uuid","usage":{"inputTokens":123,"outputTokens":456}}

event: error
data: {"code":"upstream_error","message":"..."}
```

`language` — временная замена системного промпта: язык ответа должен задаваться системным сообщением, и тогда поле из контракта уходит.

Фронтенд разбирает только эти три события. Провайдер можно менять, не трогая клиент, если сохранить формат.

## Чек-лист перехода

- [ ] Выбрать провайдера (OpenAI, Anthropic, локальная модель) и получить API-ключ
- [ ] Положить ключ в переменные окружения mock-API: `AI_PROVIDER`, `AI_API_KEY`, `AI_BASE_URL`, `AI_DEFAULT_MODEL`
- [ ] Заменить тело обработчика `POST /api/chat/completions`: вместо шаблонов — вызов провайдера в режиме стриминга
- [ ] Перевести ответ провайдера в события `delta` / `done` / `error` (у OpenAI это `stream: true` и чанки `choices[0].delta.content`)
- [x] Сохранять итоговое сообщение в хранилище со статусом `complete` при событии `done` (и частичный текст — при разрыве соединения)
- [ ] Пробросить отмену: разрыв соединения клиентом должен останавливать запрос к провайдеру
- [ ] Задать системный промпт продукта и вынести его в конфигурацию, а не в код (сейчас его роль играет поле `language` из запроса)

- [ ] Считать токены и писать их в `usage` — на этом строится лимит плана
- [ ] Обработать ошибки провайдера: таймаут, лимит запросов, недоступность модели — вернуть событие `error` с понятным текстом
- [ ] Добавить ретраи с ограничением по числу попыток только для идемпотентных сбоев
- [ ] Ограничить контекст: обрезать историю до N последних сообщений или до лимита токенов модели
- [ ] Закрыть эндпоинт авторизацией (см. `auth-integration-todo.md`) и проверкой лимита плана
- [ ] Проверить, что фронтенд работает без изменений: стриминг, остановка генерации, повторная генерация

## Что на фронтенде остаётся как есть

- Парсер SSE и буферизация чанков.
- Состояния сообщения: `pending` → `streaming` → `complete` / `error`.
- Кнопка остановки генерации: она разрывает соединение, а не имитирует остановку.
- Рендер markdown и блоков кода: к модели отношения не имеет.

## Критерии готовности

- Ответ приходит потоком, а не целиком в конце.
- Остановка генерации прекращает и поток, и работу на сервере.
- Ошибка провайдера показывается пользователю как сообщение с кнопкой «Повторить».
- Стоимость запросов учитывается в `usage` и влияет на лимит плана.
