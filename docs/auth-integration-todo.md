# Подключение реальной авторизации

## Что есть сейчас

- Формы входа и регистрации: разметка, подписи, состояния ошибок, кнопки OAuth как заглушки.
- Хук `usePreferences` хранит только настройки интерфейса — авторизации в нём нет.

## План

Целевая система — **Supabase Auth**: даёт email/пароль, OAuth (Google, GitHub) и JWT из коробки, не требуя собственного сервиса. Альтернативы: Auth0 (больше возможностей корпоративного уровня) или собственная реализация на мок-JWT, если нужно избежать внешних зависимостей.

## Что должно остаться неизменным

**Объект пользователя** — ровно те поля, что описаны в `data-model.md`:

```ts
interface User {
  id: string;
  email: string;
  name: string;
  plan: 'free' | 'plus' | 'pro';
  createdAt: string;
}
```

**Токен** — JWT с полями `sub` (id пользователя), `email`, `plan`, `iat`, `exp`. Провайдер меняется, форма токена — нет.

**Эндпоинты** — пути и формы ответов сохраняются:

| Метод | Путь                        | Ответ                        |
| ----- | --------------------------- | ---------------------------- |
| POST  | `/api/auth/signup`          | `{ user, token, expiresAt }` |
| POST  | `/api/auth/login`           | `{ user, token, expiresAt }` |
| POST  | `/api/auth/logout`          | `204`                        |
| GET   | `/api/auth/me`              | `{ user }`                   |
| GET   | `/api/auth/oauth/:provider` | редирект на провайдера       |

## Чек-лист

- [ ] Выбрать провайдера и завести проект, получить `AUTH_URL`, `AUTH_ANON_KEY`, `AUTH_JWT_SECRET` в переменные окружения mock-API
- [ ] Реализовать `POST /api/auth/signup`: валидация, хеширование пароля, создание пользователя с планом `free`
- [ ] Реализовать `POST /api/auth/login`: выдача токена, единое сообщение об ошибке для неверного email и пароля
- [ ] Реализовать `GET /api/auth/me`: чтение токена из заголовка `Authorization: Bearer`
- [ ] Решить, где хранится токен: `httpOnly` cookie (безопаснее) или `localStorage` (проще для SPA). При выборе cookie добавить защиту от CSRF
- [ ] Добавить восстановление сессии при загрузке страницы: запрос `/api/auth/me`, при 401 — переход в гостевой режим
- [ ] Подключить OAuth: кнопка Google и GitHub ведёт на `GET /api/auth/oauth/:provider`, после возврата — создание сессии
- [ ] Заменить формы: подставить валидацию (формат email, минимум 8 символов) и реальные состояния загрузки и ошибок
- [ ] Обновлять статус `plan` из подписки (см. `payment-integration-todo.md`)
- [ ] Добавить роль `admin` в токен, если понадобится админ-панель
- [ ] Защитить приватные эндпоинты middleware авторизации: диалоги, чат, биллинг
- [ ] Перенести настройки интерфейса из `localStorage` в профиль пользователя при первом входе
- [ ] Написать тесты: успешный вход, неверный пароль, истёкший токен, выход

## Как проверять

- Перезагрузка страницы сохраняет сессию.
- Выход очищает токен и возвращает гостевой интерфейс.
- Запрос к защищённому эндпоинту без токена отвечает `401` в едином формате ошибок.
