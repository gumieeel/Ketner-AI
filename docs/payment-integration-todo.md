# Подключение реальной оплаты

## Что есть сейчас

- Витрина тарифов: Free, Plus, Pro с лимитами.
- Форма оформления подписки с полями карты, без обработки платежа.
- Статус подписки в интерфейсе зашит как Free.

## План

Целевой провайдер — **Stripe** для международных платежей. Если основной рынок российский, вместо него **ЮKassa** или **CloudPayments**: контракт эндпоинтов и статусы подписки при этом не меняются, меняется только реализация внутри `POST /api/billing/checkout` и обработчик вебхуков.

## Что должно остаться неизменным

**Статусы подписки** — те же, что отдают платёжные системы:

```ts
type SubscriptionStatus = 'active' | 'trialing' | 'past_due' | 'canceled';
```

**Сущности** — `Subscription { userId, plan, status, renewsAt }` и `Plan { id, priceMonthly, ... }` из `data-model.md`.

**Эндпоинты:**

| Метод | Путь                        | Назначение                                         |
| ----- | --------------------------- | -------------------------------------------------- |
| GET   | `/api/plans`                | Каталог тарифов                                    |
| GET   | `/api/billing/subscription` | Текущая подписка пользователя                      |
| POST  | `/api/billing/checkout`     | Создание сессии оплаты, в ответе `{ checkoutUrl }` |
| POST  | `/api/billing/cancel`       | Отмена подписки в конце периода                    |
| POST  | `/api/billing/webhook`      | Приём событий провайдера                           |

## Вебхуки, которые понадобятся

| Событие Stripe                  | Что делаем                                                                |
| ------------------------------- | ------------------------------------------------------------------------- |
| `checkout.session.completed`    | Активируем подписку, ставим `status: active`, обновляем план пользователя |
| `customer.subscription.updated` | Синхронизируем план и дату продления                                      |
| `customer.subscription.deleted` | `status: canceled`, возврат на Free                                       |
| `invoice.payment_failed`        | `status: past_due`, показываем предупреждение в интерфейсе                |

Обработчик обязан быть идемпотентным: одно и то же событие может прийти повторно, поэтому результат проверяется по идентификатору события.

## Чек-лист

- [ ] Выбрать провайдера, завести аккаунт, получить `PAYMENT_SECRET_KEY`, `PAYMENT_WEBHOOK_SECRET`, `PAYMENT_PRICE_PLUS`, `PAYMENT_PRICE_PRO`
- [ ] Создать продукты и цены в панели провайдера, сопоставить их с `planId`
- [ ] Реализовать `POST /api/billing/checkout`: создание сессии оплаты, возврат ссылки
- [ ] Заменить форму карты на редирект в hosted checkout: реквизиты не должны проходить через наш фронтенд и сервер
- [ ] Реализовать `POST /api/billing/webhook` с проверкой подписи и идемпотентностью
- [ ] Обновлять `Subscription` и поле `plan` у пользователя из вебхуков, а не из ответа фронтенда
- [ ] Включить проверку лимита плана перед запросом к ИИ: Free — 10 сообщений в день, платные — без ограничения
- [ ] Считать лимит по UTC-дате, счётчик хранить на сервере, а не в браузере
- [ ] Добавить экран «Подписка оформлена» и страницу управления подпиской: план, дата продления, отмена
- [ ] Показывать `past_due` заметным предупреждением с ссылкой на обновление карты
- [ ] Тестировать на тестовых ключах провайдера и тестовых картах
- [ ] Настроить возврат на страницу настроек после успешной оплаты
- [ ] Описать ручной сценарий возврата средств и удаления аккаунта

## Требования, которые нельзя нарушить

- Данные карты никогда не попадают на наш сервер: только hosted checkout или токенизация на стороне провайдера.
- План пользователя меняется только по подтверждённому вебхуку.
- Понижение до Free не удаляет историю диалогов, но закрывает доступ к новым сообщениям сверх лимита.
