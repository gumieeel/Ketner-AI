## 2. Архитектурные проблемы, которые нужно решить до новых функций

Каждая проблема — с безопасным вариантом решения. Пункты 1, 2, 7 и 8 выполнены на этапе «Подготовка»; 3–6 выполняются на этапе 2.

1. **Чужие диалоги (R1) — исправлено.** `conversationStore.get` ищет только среди диалогов пользователя. Перенос гостевого диалога в аккаунт — явный `claimGuestConversation`: только если диалог сейчас принадлежит гостю из заголовка `X-Guest-Id` этого браузера (сайт присылает его и после входа). В Postgres владелец меняется условием `WHERE user_id = <гость>`. Регрессионные тесты — `security-regressions.test.ts`.
2. **Нет миграций (R2) — сделан раннер.** Собственный, без drizzle-kit: `db/migrate.ts` создаёт `schema_migrations` и применяет миграции из `db/migration-list.ts` (SQL в TypeScript, чтобы попадал в сборку) по порядку, каждую в своей транзакции под advisory-lock, с контрольной суммой; изменённая применённая миграция останавливает раннер. Запускается в `initDatabaseSync` после остальной синхронизации, в отдельном `try`: сбой выключает только функции, которым нужны новые таблицы (`getMigrationState()`). Проверено на Postgres 16. Существующие `CREATE … IF NOT EXISTS` в `db/sync.ts` остаются как есть; устаревший `0000_init.sql` пока не трогаем.
3. **Асинхронное зеркало вместо записи (R3, R4).** Новые сущности не кладутся в `DocStore` и `ketner_docs`: отдельные таблицы, чтение и запись прямыми параметризованными запросами с `user_id` в каждом `WHERE`, как у `code_projects`. Ответ API уходит после подтверждённой записи. Для локального запуска без `DATABASE_URL` и тестов — реализация того же интерфейса в памяти.
4. **Шлюз без структурированного вывода (R5).** Предлагаю: расширить `GatewayRequest.task.kind` до `'review' | 'discovery' | 'solution_test' | 'solution_run'`, собирать текст ответа из `onDelta`, разбирать `extractJsonObject` и проверять схемой. При невалидном JSON — один повтор с сообщением об ошибке разбора; второй сбой — ошибка этапа без выдуманного результата. Выбор модели и fallback — штатные, `strictModel` не используется.
5. **Fair Use блокирует служебные задачи.** Сейчас `FairUseEngine.evaluate` отказывает и задачам `review`, если пользователь исчерпал 10 сообщений чата в сутки. Для анализов нужен свой счётчик (квота анализов) и правило: служебные задачи не блокируются чатовым суточным лимитом, но проходят проверки минуты, часа, параллельности и токенов.
6. **Нет идемпотентности списания (R6).** Защита на уровне операции: клиент шлёт `Idempotency-Key`; уникальный индекс `(user_id, idempotency_key)` в таблицах запусков; повтор возвращает сохранённый результат, а этап анализа со статусом `running` или `done` повторно модель не вызывает.
7. **Валидация (R12) — добавлен `zod`** (`^4.6.7`) явной зависимостью сервера: схемы ответов моделей и тел запросов новых маршрутов.
8. **Нет CI (R8) — добавлен** `.github/workflows/ci.yml`: на каждый пуш в `main` и pull request — `npm ci`, Prettier, типы, ESLint, тесты, сборка, сверка закоммиченного `apps/web/dist` со сборкой (без `.prerender.json` с датами), `npm audit --omit=dev --audit-level=high`.
9. **Гости проходят анализ целиком (решение владельца).** Анализ и отчёт гостя принадлежат его `guest_…` id и ограничены по IP, как гостевой чат; после входа переносятся в аккаунт тем же правилом, что диалоги. Builder и планы с сохранением — только после входа.

## 4. Как исключить регрессии

- Существующие контракты `/api/*` и `/v1/*` не меняются; новые маршруты — под новыми префиксами `/api/analyses`, `/api/plans`, `/api/solutions`.
- Изменения шлюза — только аддитивные (новые значения `task.kind`), с тестами в `ai/gateway.test.ts`, что чат, сравнение и проверка ведут себя как раньше.
- Каждая фаза — отдельные коммиты; после каждой: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, сверка `dist`, ручная проверка `/`, `/chat`, `/pricing`, `/code` на 375 и 1440 px.
- Новые функции за флагом окружения `DISCOVERY_ENABLED` (по умолчанию выключен в production до приёмки фазы 4): маршруты отвечают 404, главная показывает текущий лендинг. Это позволяет выкатывать код в `main` без влияния на пользователей.
- Тесты на изоляцию данных: для каждой новой сущности — попытка чтения, изменения и удаления чужой записи даёт 404.
- Тесты денег: повтор запроса с тем же `Idempotency-Key` не списывает кредиты второй раз; ошибка модели не списывает; нехватка кредитов даёт понятную ошибку, а не частичный результат.

## 8. Риски этого плана

| Риск                                                         | Что делаем                                                                                                                                                                           |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Качество структурированного JSON на дешёвых моделях          | Схема + один повтор; модели этапов выбираются по замерам, а не по названию; результат с ошибкой разбора не показывается как готовый                                                  |
| Стоимость анализа съедает пробные 200 кредитов               | Бюджет на этап (`maxCostUsd`), показ оценки до запуска, квота анализов, повтор только при изменении ответов                                                                          |
| Модель выдумывает возможности, которые Ketner не умеет       | Статус реализуемости считает код по каталогу возможностей, а не модель; модель может только понизить статус                                                                          |
| Выдуманные цифры экономии                                    | Impact Estimator возвращает цифры только из ответов пользователя с формулой и допущениями; без исходных данных — качественная оценка                                                 |
| Prompt injection в описании задачи и тестовых данных         | Пользовательский текст передаётся как данные в отдельном сообщении с разметкой; ответ модели никогда не исполняется как команда; решения не имеют инструментов с внешними действиями |
| Потеря долгого анализа при перезапуске                       | Статус и результаты каждого этапа в базе; незавершённый этап возобновляется при следующем запросе статуса                                                                            |
| Новая главная снижает SEO по запросам «ChatGPT в одном чате» | Главная получает новое позиционирование, прежний посыл и title переходят на `/models` (решение владельца)                                                                            |
| Регрессия в чате из-за правок шлюза                          | Только аддитивные изменения, тесты чата, сравнения и проверки в каждом этапе                                                                                                         |

## 10. Решения владельца (30.10.2026)

1. **Гости** проходят весь анализ и получают отчёт без входа. Создание решений (Builder) — после входа.
2. **Бесплатный сценарий** — один анализ в сутки и краткий план одной выбранной возможности, без списания пробных 200 кредитов; Builder в него не входит. Дополнительные анализы и планы — за кредиты.
3. **Проверка данных** — `zod`.
4. **Прежняя главная**: содержательные разделы переносятся на `/models` и `/pricing`; исходная версия сохраняется до переноса (тег git и копия кода).
5. **Заголовок главной** — новое позиционирование; прежний посыл («ChatGPT, Claude, Gemini и Grok в одном ИИ-чате») остаётся на странице моделей.
6. **Первое решение Builder** — персональный ИИ-помощник, которого действительно можно настроить и протестировать.
7. **Модели** — GPT-6 Luna для бесплатного сценария, MiMo-V2.6 Pro для анализа и плана за кредиты, Claude Sonnet 5.5 для «Глубокого анализа»; без автоматической подмены модели. В документах и интерфейсе Discovery — настоящие названия моделей.
8. **Бюджет бесплатных анализов** — $5 в сутки, отдельно от расходов чата и других разделов: резерв до запуска, расчёт по факту, остановка новых бесплатных анализов при исчерпании, возобновление после сброса; лимиты на пользователя и защита от множества аккаунтов.
