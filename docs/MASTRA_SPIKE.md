# Спайк Mastra (T4.0): отчёт и рекомендация

Составлено 11.11.2026. Код — в отдельной ветке **`claude/mastra-spike`** (коммит `39b2dad`), в `main` не сливается, к маршрутам не подключён. Статус — **отчёт, ждёт решения владельца**.

## 1. Итог

**Рекомендация: собственный цикл агента поверх `AIGateway`; Mastra сейчас не вводить.** `runtime = 'mastra'` в ограничения базы не закладывать (в `platform/runtime-binding.ts` Mastra и так «недоступен»).

Что показал спайк:

- **Mastra работает поверх нашего шлюза.** Бот для клиентов (AgentSpec) ответил через Mastra с одним вызовом инструмента `knowledge.search`. Модель для Mastra — тонкий мост в `AIGateway`: выбор модели, запасные модели, цена, запись учёта и списание кредитов остаются у шлюза. Ключей провайдеров Mastra не видит.
- **Учёт и списание — как у прежнего пути бота.** Каждый шаг модели даёт ровно такую же запись учёта (`kind: 'assistant'`, `runId` = id решения, та же модель, провайдер, источник), цена — от провайдера, кредиты владельца уменьшились ровно на сумму шагов.
- **Тот же результат даёт собственный цикл в 60 строк** поверх того же шага шлюза — без 132 пакетов, +110 МБ памяти и двух опасных настроек по умолчанию (раздел 4).
- **Изменение шлюза нужно в обоих вариантах.** В чат-шлюзе (`gateway.ts`) не было вызова функций: он есть только у провайдеров (`streamAgent`) и в публичном `/v1` (`AgentGateway`). Спайк добавил в `AIGateway` необязательный `agentStep` (+102 строки) — это и есть T4.1, и он нужен независимо от выбора.

## 4. Найденные риски Mastra

| # | Риск | Что показал спайк | Мера |
| --- | --- | --- | --- |
| R1 | **Повторы вызова модели по умолчанию** | `maxRetries` по умолчанию 2. Повторяется **любая** ошибка, кроме `APICallError` AI SDK, поэтому ошибка нашего шлюза повторялась бы. Тест: при сбое всех провайдеров шлюз вызывается **3 раза** с настройкой по умолчанию и **1 раз** с `maxRetries: 0`. Каждый повтор прогоняет всю цепочку запасных моделей шлюза | В спайке `maxRetries: 0` обязателен; повторы и запасные модели — только у шлюза |
| R2 | **Телеметрия включена по умолчанию** | Модуль `feature-telemetry` шлёт события в `us.posthog.com`: хеш имени хоста, ОС, версия Node, может читать git remote. Выключается `MASTRA_TELEMETRY_DISABLED=true`. В прогоне спайка (только `Agent` без класса `Mastra`) модуль телеметрии **не загрузился**, исходящих соединений — **0** (тест считает соединения). Класс `Mastra` модуль телеметрии импортирует | Если когда-нибудь использовать класс `Mastra` — `MASTRA_TELEMETRY_DISABLED=true` в окружении и проверка соединений в тестах |
| R3 | **Память и старт** | +110–124 МБ RSS и +0,5 с на импорт | Существенно для небольшого экземпляра Render; измерить на production-сборке перед решением |
| R4 | **Частые выпуски** | Минорная версия примерно каждую неделю | Точная версия, обновление отдельной задачей с прогоном тестов спайка |
| R5 | **Свой системный промпт и свои хранилища** | Mastra добавляет свои `instructions` и умеет хранить память, процессы, трассы в своих таблицах — это пересекается с нашим хранением (`executions`, `execution_events`, `execution_effects`). В спайке мост отбрасывает системные сообщения Mastra (системный промпт бота строит шлюз), память и хранилища Mastra не используются | При внедрении — запрет хранилищ Mastra, единый журнал исполнений Ketner |
| R6 | **Типы из пакета-псевдонима** | Тип `LanguageModelV2` взят из `@ai-sdk/provider-v5`, который ставит Mastra | Явная зависимость при переносе |

## 5. Мост в AIGateway

**Изменение шлюза** (`ai/gateway.ts`, `ai/gateway-types.ts`, +102 строки): необязательное поле `GatewayRequest.agentStep` — сообщения шага агента и инструменты. Если оно есть:

- провайдер без вызова функций пропускается — цепочка идёт к следующей модели;
- вызов идёт через `provider.streamAgent` с инструментами вместо `streamText`;
- провайдер получает системный промпт, который построил шлюз (у бота — его настройки целиком, как на прежнем пути), и сообщения шага;
- успех — текст **или** вызов инструмента;
- семантический кэш не читается и не пишется;
- `onDone` возвращает `toolCalls`;
- всё остальное без изменений: выбор модели, запасные модели, предохранитель, цена, запись учёта (`kind: 'assistant'`, `runId`), списание с потолком `maxChargeUsd`.

**Не сделано в спайке** (нужно при переносе в `main`, T4.1):

- сторож стрима для шага агента (сейчас только сигнал отмены);
- поток частей вызова инструмента в интерфейс.

**Шаг шлюза** (`gateway-step.ts`): запрос — ровно как у бота в `builder/service.ts` → `answer()`:

- `assistant` с `replaceSystemPrompt`;
- потолок ответа 600 токенов;
- потолок списания $0,03 = 30 кредитов;
- плюс `agentStep`.

**Модель для Mastra** (`ketner-language-model.ts`, 173 строки): `LanguageModelV2` с `doGenerate` и `doStream`. Перевод подсказки Mastra в сообщения шага: системные сообщения отбрасываются, вызовы и результаты инструментов переводятся. Mastra в спайке вызывал `doGenerate`.

**Агент** (`mastra-agent.ts`): `new Agent({ model, tools, maxRetries: 0 })`, `generate(…, { maxSteps: spec.limits.maxSteps })`. Инструменты строятся из `AgentSpec.allowedActions`. Перед вызовом проверяется, что действие разрешено агенту и по риску не требует одобрения (`platform/risk.ts`, `legacyApprovalPolicy('customer_bot')`).

**Что Mastra дал бы, а нам пришлось бы писать самим:**

| Возможность | Сейчас у нас | Нужно ли на ближайших этапах |
| --- | --- | --- |
| Цикл шагов с инструментами, лимит шагов | 60 строк (`own-loop.ts`) | Да — уже есть |
| Проверка входа инструментов по схеме | Zod уже в проекте | Да — 10–20 строк |
| Приостановка до одобрения человеком (suspend/resume) | Проект `approval_requests`, `execution_effects` (T1.5, 0016–0017) | Да — свой, связан с нашим журналом и биллингом |
| Память диалога | Своя история бота | Да — уже есть |
| Трассы и наблюдаемость | `execution_events` (0017), `UsageRecord` | Да — свой журнал |
| Процессы (workflows), сети агентов, MCP, голос, оценки (evals) | Нет | Не на ближайших этапах (процессы — n8n, этап 6) |
| Структурированный ответ | Есть `response_format` в `AgentGateway` | По мере надобности |

**Вывод.** Ближайшим этапам (бот и личный помощник на платформе, одобрения, журнал исполнений, биллинг) нужен цикл с инструментами поверх нашего шлюза. Он занимает 60 строк, а то, что сложно — права, одобрения, журнал, идемпотентность списаний — всё равно наше и связано с нашей базой. Mastra окупился бы при сетях агентов, MCP, оценках или своих процессах. Тогда спайк показывает, что подключить его можно поверх того же шага шлюза без изменения учёта: мост 173 строки, `maxRetries: 0`, телеметрия выключена.
