## 2. Чего не было

1. **Сметы внедрения.** Ни каталога работ, ни часов, ни ставок, ни денег в тенге. Возможность имела только ярлык `effort: low/medium/high` от модели.
2. **Структурированного профиля бизнеса** (отрасль, город, каналы, объём) — только свободный `context`.
3. **Заявок на внедрение** и их жизненного цикла; админки для проверки смет; журнала изменений цен; фактических данных проектов и калибровки.
4. **Работ, которые делает команда** (Telegram, WhatsApp, Google Таблицы, CRM): платформенный каталог честно помечает их «нет», и для сметы нужен второй, отдельный каталог работ команды.
5. **KZT** нигде в коде; курс USD→KZT не задан.

## 3. Ограничения и совместимость

- **Хранение.** Новые таблицы — только миграциями (`0012`), запись подтверждается до ответа API (как у анализов), без JSON-файлов в памяти.
- **Один процесс.** Лимиты частоты в памяти (существующий `RateLimiter`); после перезапуска счётчики заявок сбрасываются — приемлемо, у заявок есть идемпотентность в базе.
- **Потолок ответа модели.** Поиск возможностей теперь возвращает ещё и работы по внедрению: потолок вывода поднят (бесплатный и платный 4 000 → 5 000 токенов, глубокий 8 000 → 9 500). Потолок цены этапа считается автоматически; цены анализа на странице «Кредиты» (`plan-facts.json`) обновлены: за кредиты ≈10 / не больше 33 (было 9 / 29), глубокий ≈91 / не больше 370 (было 79 / 328). Бюджет бесплатных анализов $5/сутки не менялся — бесплатных анализов в сутки станет чуть меньше на пределе бюджета.
- **Старые анализы** не имеют работ: смета выводится из платформенных требований (`deriveWorkItems`) с низкой уверенностью и пометкой «нужна проверка».
- **Сайт закоммичен собранным** (`apps/web/dist`), пререндер главной проверяется тестами — сборка обязательна перед выкладкой.

## 4. Риски безопасности

| Риск                                   | Состояние | Что сделано                                                                                                                                                                                                                                                                             |
| -------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| В Supabase нет RLS ни на одной таблице | Было      | Новые таблицы `0012` создаются с `ENABLE ROW LEVEL SECURITY` без политик: роли `anon`/`authenticated` API Supabase их не читают; сервер работает владельцем таблиц и не затронут. Старые таблицы — отдельная задача (риск: при утечке anon-ключа Supabase они читаются через PostgREST) |
| Цены из ответа модели                  | Новое     | Модель не пишет часы и деньги; схема их не принимает; незнакомые id работ помечаются, а не считаются                                                                                                                                                                                    |
| Доступ к чужим сметам и заявкам        | Новое     | Сметы — только через анализ владельца; заявки — по `user_id` из сессии; чужое — 404; тесты на это есть                                                                                                                                                                                  |
| Подмена суммы клиентом                 | Новое     | Тело заявки содержит только `scopeKey`, контакт и текст; сумма берётся из сохранённой сметы на сервере                                                                                                                                                                                  |
| Утечка внутренней экономики            | Новое     | Клиенту не отдаются часы и деньги по строкам, ставка, множители, резерв, заметки, факт; проверяется тестом по тексту ответа                                                                                                                                                             |
| Изменение цен задним числом            | Новое     | Версии настроек неизменяемы; смета и заявка хранят снимок и номер версии                                                                                                                                                                                                                |
| Bearer-токен в `localStorage` (XSS)    | Было (R9) | Не менялось; новые страницы не выводят HTML из данных                                                                                                                                                                                                                                   |

## 5. Правовые вопросы (требуют отдельной проверки юристом)

Закон РК «О персональных данных и их защите»: согласие на обработку, хранение на территории РК (база сейчас в Supabase, Франкфурт), трансграничная передача описаний бизнеса провайдерам моделей (OpenRouter и вендоры — вне РК), сроки хранения. Технические меры (RLS, проверки владельца, удаление содержимого анализа) **не означают соответствия закону**. Контакт в заявке (имя, телефон) — персональные данные: собираются только при явной отправке заявки.
