Составлено 07.11.2026 по спецификации «KETNER AI — FULL PLATFORM TRANSFORMATION» (агенты, Mastra, n8n, RAG) и по коду ветки на коммите `6a40100`. Это разбор, а не реализация: код не менялся. _Вторая редакция (свой исполнитель + Activepieces) заменена; сравнение сохранено в [WORKFLOW_ENGINE_DECISION.md](WORKFLOW_ENGINE_DECISION.md)._

- **Discovery** в два этапа (профиль + вопросы → возможности), карта из 5 областей, бюджет бесплатных анализов, модельная политика этапов — `discovery/*`.

## 3. Внешние факты (проверено 07.11.2026)

**Mastra**

- `@mastra/core` 1.82.0, `@mastra/pg` 1.35.0, `@mastra/memory` 1.41.0 — Apache-2.0; требуют Node ≥ 22.13.0. В проекте `engines.node >=22.12.0` → поднять до 22.13 (Dockerfile уже Node 24, локально 22.23). Zod: `^3.25 || ^4` — совместимо с `zod` 4.6.
- Код в каталогах `ee/` (например, `@mastra/core/auth/ee`, `@mastra/editor/ee`) — под отдельной Mastra Enterprise License, в production нужен письменный договор. Эти части не использовать.
- Модель подключается как AI SDK `LanguageModelV2`: через свой `MastraModelGateway` (метод `resolve`) или OpenAI-совместимый `{ id, url }`. Значит, мост к AIGateway — это реализация `LanguageModelV2`, которая внутри вызывает наш шлюз (учёт, кредиты, запасные модели сохраняются). Вариант «OpenAI-совместимый URL на наш `/v1`» проще, но гонит вызов через HTTP и ключ `ketner_sk_…` — хуже для учёта по агентам.
- Вопрос, который нужно решить спайком (T4.0): у Ketner уже есть свой цикл агента с инструментами (`AgentGateway`). Mastra оправдан, если берём её инструменты, workflows, память и трассировку; если нужен только цикл «модель → инструмент → модель», он дешевле на своём коде. Спецификация требует Mastra — спайк должен показать цену зависимости (размер, транзитивные пакеты AI SDK, время сборки).

**n8n Community Edition** (выбран 07.11.2026; подробно — [N8N_DEPLOYMENT.md](N8N_DEPLOYMENT.md))

- Версия 2.46.6, образ `docker.n8n.io/n8nio/n8n`; Postgres 16–18; лицензия — Sustainable Use License (текст проверен по `LICENSE.md` репозитория n8n). Файлы `.ee.` — только с Enterprise-лицензией.
- Официальный FAQ n8n по лицензии: можно собирать процессы для клиентов, брать плату за создание и сопровождение, давать клиентам запускать готовые процессы и подключать свои аккаунты. Нельзя давать клиентам строить или настраивать логику — «via a custom UI, our API, MCP, or an AI agent acting on the user's behalf».
- В CE нет проектов, общего доступа, внешних хранилищ секретов, окружений, SSO, log streaming, пользовательских переменных; queue mode есть. права API-ключа в 2.46.6 выбираются при создании и соблюдаются (проверено на стенде).
- Публичный API: `X-N8N-API-KEY`; запуск процесса — только через вебхук. Безопасность: `NODES_INCLUDE`/`NODES_EXCLUDE`, `N8N_BLOCK_ENV_ACCESS_IN_NODE`, SSRF-защита, таймауты и очистка истории запусков — переменными окружения.

**Activepieces** (отложен 07.11.2026; сравнение — [WORKFLOW_ENGINE_DECISION.md](WORKFLOW_ENGINE_DECISION.md))

- Ядро — MIT; `packages/ee/` и `packages/server/api/src/app/ee` — Enterprise License: production только по подписке/договору, разработка и тесты бесплатно.
- В Community Edition нет публичного API с ключами, проектов на клиента, ролей, списка разрешённых интеграций (piece sets), аудита, глобальных подключений, частных pieces и встраивания — всё это Enterprise/Cloud. Сервер-сервер с CE — только через внутренний API от имени служебного пользователя.
- Открытый лицензионный вопрос: сборка COMMUNITY сама регистрирует модуль из `ee/projects`. Нужен письменный ответ Activepieces.
- Сильные стороны: устойчивые прогоны с контрольными точками, V8-песочница `SANDBOX_CODE_ONLY` для многоарендной работы, ожидание одобрения и задержки, сотни готовых интеграций. Прод: app + воркеры (1 ГБ на одновременный flow) + Redis + своя Postgres + S3.

**Postgres / Supabase**

- `pgvector` в Supabase включается расширением `vector` (`CREATE EXTENSION vector`); полнотекстовый поиск (`tsvector`, `GIN`) есть из коробки. Для русского текста — конфигурация `russian`. В CI-образе `postgres:16` расширения `vector` нет → тесты RAG с векторами нужен образ `pgvector/pgvector:pg16`.
- Эмбеддинги: через OpenRouter их нет в привычном виде — нужен провайдер эмбеддингов и учёт их стоимости в том же шлюзе (новый `kind: 'embedding'`).
